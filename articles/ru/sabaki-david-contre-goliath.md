## Введение

Если ты с сентября сидишь на Hacker News или в Twitter, ты точно видел Jev.

15 сентября 2026 TypeSafe выпускает Jev, свой первый "System One". Питч укладывается в одну фразу : хватит просить LLM сгенерировать JSON, чтобы выбрать лейбл. Даёшь ему `state` плюс типизированные вопросы, он возвращает тебе типизированные решения с вероятностями. Один проход, ноль токенов на семплирование, ничего парсить на выходе.

Это взлетело. Рекордный первый день адопшена на Vercel AI Gateway, пять клиентов на Elixir за несколько дней, все бенчмаркают Jev против своей штуки. И честно, хайп понятен. Мы годами колхозили промпты `отвечай ТОЛЬКО {"choice": ...}` и молились, чтобы модель не выдумала опцию, не сломала JSON, не галлюцинировала поле. Jev дал этой потребности имя и зашипил чистое API : `POST /v1/systemone`, вопросы `choice / score / noul`, ответы с `probabilities` + `confidence`.

Мне идея зашла. Эко-модель, меньше -- и чтобы было ясно, я за Jev никогда не платил.

Потому что под капотом Jev всё равно закрытое API. Веса неизвестны, селф-хоста нет, каждое решение = сетевой round-trip + счётчик, который крутится. А опенсорсные альтернативы, которые вышли следом, весят под 400M параметров с обязательным GPU.

Поэтому я построил другую крайность : [Sabaki](https://sabaki.fox3000foxy.com/). Роутер по ключевым словам + логистическая регрессия на чистом TypeScript, которые говорят на том же контракте, что Jev (те же шейпы `choice / score / noul`, тот же эндпоинт `/v1/systemone`), но крутятся за **меньше 1ms** с JSON в **20 килобайт**. Ноль зависимостей в nano-режиме, офлайн, 0€.

Для масштаба : Laya это 843 Мб safetensors под загрузку. OpenDecider-nano это 2 Гб RAM. Sabaki nano invoices это 20 Кб. Разница в весе где-то в **40 000** раз.

Если хочешь строгую версию с цифрами, есть препринт v1 от октября 2026 на сайте : *Sabaki: An Organizational Mixture-of-Experts for Typed Decisions on CPU* ([PDF](/assets/paper/sabaki-organizational-moe-typed-decisions.pdf)). Дизайн, замеры, трейдоффы, всё там. А эта статья -- читаемая версия, с открытым кодом рядом.

Я писал это не в углу в режиме бумажного бенчмарка. Я контрибьючу в [azalio/doomLaya](https://github.com/azalio/doomLaya) (мой форк : [fox3000foxy/doomLaya](https://github.com/fox3000foxy/doomLaya)), харнесс, где Laya и Jev реально играют во FreeDoom с model-owned решениями, телеметрией по тикам и видосами. Я видел Голиафа в игре вживую, и как только сеть чихает, он тоже.

Давай вскрывать движки по одному. Как обычно, с настоящим кодом.

## Ринг, на котором согласны драться все

Есть один датасет, который цитируют Jev, Laya и OpenDecider : [LocalLLaMA/typed-decisions](https://huggingface.co/datasets/LocalLLaMA/typed-decisions). 4 синтетических воркфлоу (поддержка, счета, секьюрность, трейсы агентов), 5 вопросов на кейс, 1200 кейсов в трейне, 400 в тесте, 2000 решений.

| Модель | Параметры | Скор на тесте | Латентность | Где крутится |
|---|---|---|---|---|
| OpenDecider-nano | ~400M | 0.796 | 17ms GPU | GPU, 2 Гб RAM |
| Laya typed-decisions | 421M | 0.766 | ~25s/state CPU, ~830ms/кейс MLX | GPU |
| Jev 1.13 | закрыт | ~0.73-0.75 | ~710ms API | только API |
| **Sabaki mini** | 22M int8 | **0.69** | **~20ms CPU** | CPU, 22 Мб |
| **Sabaki nano** | ~0 | **0.61** | **<1ms** | везде |
| Laya base zero-shot | 421M | 0.362 | так же | GPU |

Рандом это 0.318, мажорити 0.461. Так что Laya base с 0.362 без файн-тюна, это уровень "отвечаю наугад, но вежливо". Запомни это, пригодится.

7 пунктов отделяют Sabaki от лучшего. 1000x латентности отделяют их в другую сторону, когда у тебя нет GPU. Вот тебе вся статья в двух фразах, остальное -- чтобы понять почему.

Только осторожно : за одинаковой розеткой `choice / score / noul` кухни совершенно разные. Jev = закрытое API. Laya = дообученный ModernBERT-large. OpenDecider = дистиллированный Ettin-encoder. Sabaki = подсчёт слов + MiniLM int8. Один контракт, несравнимые бюджеты.

## Jev, пощёчина, которую видели все

Отдадим TypeSafe должное : контракт System One, это реально хорошая идея.

Раньше, чтобы рассортировать тикет, ты делал так : просил LLM "выбери между billing, technical и spam, ответь в JSON", парсил ответ, разгревал случаи, когда он отвечает "Я бы сказал billing! 😊" или выдумывает 4-ю категорию. Каждый вопрос стоил токенов, каждый ответ мог сломать пайплайн.

Jev меняет сделку : ты шлёшь текст + вопросы с их критериями, он оценивает каждый вопрос параллельно и возвращает типизированное значение с его распределением.

```bash
curl https://api.typesafe.ai/v1/systemone \
 -H "Authorization: Bearer $KEY" \
 -H 'content-type: application/json' \
 -d '{"state":"charge double ce mois-ci","questions":{"dept":{"type":"choice","instructions":"Route ce message.","criteria":{"billing":"paiements","technical":"bugs"}}}}}'
```

Ответ : `{ choice, probabilities, confidence }`. Никакого свободного текста. Твой код может ветвиться прямо по нему.

Поэтому это и стало вирусным : SDK на Python + JS, плагин Claude Code, интеграция LangChain, все могли посадить своих агентов на него за полдня. Дока TypeSafe даже толкает здоровый паттерн : Jev для мелких быстрых суждений, детерминированный код вокруг для сборки настоящего решения, медленный LLM или человек как только уверенность низкая.

Беда в остальном. Веса закрыты, офлайн невозможен, цена за вызов. Для агента, который принимает 100 решений за ран, налог кусается. Для Doom на 35 тиков/с это смерть : в doomLaya Jev проходит MAP01 seed 48 за 68.97s с p50 HTTP 357ms. Ран приносит $0.0046 цены API -- не мой счёт, а счёт бенчмарка. Это работает, ран чистый, без смертей. Но 357ms при 35 тиках/с, это 12 тиков, пока игра идёт дальше, а ты ждёшь сеть.

Sabaki спёр ровно этот контракт -- те же вопросы, те же ответы, тот же эндпоинт `/v1/systemone`, который отдаёт `serve()` -- выкинув всё, что требует дата-центр.

## Laya, жирный опенсорс, который показал, что можно без API

[Laya](https://github.com/NandhaKishorM/laya) от Convai Innovations, Apache-2.0. Под капотом : ModernBERT-large, 421M, с 1 токеном `[MASK]` на опцию. Хиден-стейт каждого маркера идёт в маленький MLP, софтмакс по опциям вопроса. Один проход на вопрос, как у Jev.

```python
pipe = pipeline("text-classification", model="convaiinnovations/laya-typed-decisions")
```

На 0.766 стоит остановиться. Это чекпоинт **дообученный на трейне бенчмарка** : 1200 кейсов, RLCD с гауссовым шумом на логитах, reward log + spherical. Та же модель без этого фита падает до 0.362. Считай, гадает. Так что скор Laya, это "жирный энкодер + обучение на домене", а не "жирный энкодер-магия".

На CPU это кирпич. Замеренный ONNX-порт крутится около 25s на state. На MLX FP16 считай 830ms на кейс в среднем с p99 5.3s. И надо загрузить 843 Мб прежде чем вообще что-то ответить.

В doomLaya стоковая Laya валит MAP01 за 180s. Адаптированная v3 ([azalio/laya-doom-v3](https://huggingface.co/azalio/laya-doom-v3)), переобученная на Doom, выходит за 61.43s с p50 108ms на MPS, по пути подбирая шотган. Так что да, это играет -- после dedicated-обучения, на Apple GPU, со скриптованным экзекьютором, который делает настоящую работу (A*, двери с латчем 15 тиков, автонаведение).

Мой итог : без обучения на твоей задаче Laya служит тебе буфером обмена за 421M. С ним -- очень сильно, но давай GPU и данные в комплекте.

## OpenDecider, тот, кто выиграл лидерборд

[OpenDecider](https://github.com/manjunathshiva/opendecider), это Manjunath, который решил забрать всех на их же бенчмарке. Итог : **0.796** с Ettin-encoder-400m в полном файн-тюне + MLP-голова, KL-лосс на софт-таргетах, дистиллированных из Qwen3-235B + DeepSeek.

```bash
pip install opendecider
# 17ms/вопрос на L40S, 18ms на M4 Max, ~9ms в батче
```

При 50% coverage selective accuracy растёт до 0.943 против 0.882 у Jev. На бумаге лучшее из двух миров : опен, откалиброван, быстр.

На практике : 2 Гб RAM чтобы загрузить nano, GPU обязателен чтобы держать 17ms, фишинг 0.63 против 0.90 у Jev (OOD его умывает), и как Laya, обучен на трейне бенчмарка. Тест никто не видел, но домен -- да.

Армрестлинг он выигрывает, но это всё равно 400M с GPU за спиной. Ты его не засунешь в Cloudflare Worker или в игровой цикл на ноуте.

## 150M, и дыра под ними

openJev-verdict-2.0 (151M), julia-1 (144M мультиязычная), Open Jev (150M), Largha-150M (144M en+zh), Vela (0.3B-9B). Все ModernBERT или mmBERT-small, все умеют крутиться на CPU, все приятно обучать (Open Jev заявляет 30 мин на T4 в Colab). Цифры self-reported, протоколы разные, так что бери с щипцами, но семейка существует.

Дженералист Sabaki весит **22.7M**. Примерно в 6.5x меньше самого мелкого в этой банде. Никто другой не спускается ниже 100M чтобы отвечать на вопросы, заданные в рантайме.

Вот что такое "самый мелкий в мире" : не лучший скор, а самая маленькая упаковка, которая читает твои `instructions` + `criteria` и решает, когда ни один специалист ответить не может.

## Sabaki, тупой роутер и его одноразовые эксперты

Так, хорош о жирных. Переходим к Давиду, потому что тут начинается веселье.

Sabaki не пытается быть жирной умной моделью, которая понимает мир. Это организационный MoE : 1 разреженный роутер на уровне системы, независимые эксперты, один активный на инпут. Каждый плагин -- отдельный npm-пакет, со своим манифестом, весами, версией. Ставишь только то, что роутишь.

Орга [sabaki-js](https://github.com/sabaki-js) : 13 репо, ядро `sabaki` (129 коммитов), 6 плагинов `@sabaki-js/*`, веса, Cloudflare-воркер, шаблон чтобы написать свой.

`package.json` ядра уже рассказывает историю :

```json
"dependencies": { "@typesafe-ai/sdk": "^0.7.0" },
"optionalDependencies": { "onnxruntime-node": "^1.22.0" }
```

В nano-режиме ноль рантайм-зависимостей. Только скомпилированный TypeScript, ставить нечего, ломаться между версиями ONNX нечему.

### Роутер, или как решать в несколько строк

Роутер живёт в `src/index.ts`, а токенизация выглядит так (`src/index.ts:129`) :

```ts
function tokens(s: string): string[] {
  return s.toLowerCase().normalize("NFD").replace(/[̀-ͯ]/g, "")
    .split(/[^a-z0-9]+/).filter((w) => w.length > 3);
}
```

Нижний регистр, акценты снесены, слова от 4 букв. Этот фильтр выкидывает весь шум ("le", "de", "ok"). На саппорт-тикетах это всё меняет, потому что матчишься по словам, которые несут смысл.

Сам скоринг лежит в `route()` (`src/index.ts:251`), и тут решается всё :

```ts
const hits = kws.filter((k) =>
  words.some((w) => w.includes(k) || k.includes(w))).length;
const score = hits / Math.sqrt(kws.length);
```

Матчинг свободный в обе стороны : `billing` цепляет `billed`, `invoice` цепляет `invoicing`. Деление на корень не даёт задавить большим спискам кейвордов, иначе мейл-плагин со своими 600 словами выжирал бы всех, как только в письме есть "hello".

У каждого плагина свой порог, дефолт 0.15 лежит в `src/index.ts:139`, у мейла 0.03 потому что темы короткие. Ниже :

```ts
return { domain: "unknown", decision: null, confidence: 0, plugin: null };
```

Неизвестный домен = `unknown`, никогда никакого выдуманного гесса чтобы порадовать. Подход нарочно тупой, и ровно поэтому потом работает порог `automate > 0.8` : когда Sabaki отвечает, значит реально сматчился специалист.

Впридачу есть языковая ось через `langid` : плагин, который заявляет `languages`, конкурирует только за свои языки. Удобно разводить латинский фишинг и CJK. Текст слишком короткий = без фильтра, конкурируют все.

Итоговая цена : несколько микросекунд на решение. Никаких матриц умножать, никаких сетей дёргать, только сравнения строк и одно деление.

### Nano, мой любимый файл в репо

`src/logreg.ts:28`, токенизация :

```ts
function tokens(s: string): string[] {
  const words = s.toLowerCase().split(/[^a-z0-9]+/)
    .filter((w) => /^[a-z]{3,}$/.test(w));
  const out = [...words];
  for (let i = 0; i < words.length - 1; i++)
    out.push(`${words[i]} ${words[i + 1]}`);
  return out;
}
```

Униграммы + биграммы. `charged twice` даёт `charged`, `twice`, и пару `charged twice`. Этого хватает чтобы поймать "двойное списание" без транса на 400M.

`src/logreg.ts:46`, векторизация, где TF-IDF делает работу :

```ts
const tf = 1 + Math.log(c);  // сублинейный TF
const val = tf * w.idf[i]!;  // сглаженный IDF как в sklearn
```

10-е вхождение слова весит меньше первого, редкие слова весят больше чем "please". Ровно рецепт sklearn, точная паритетность проверена на 20 вопросах.

И коммент, который заставил меня улыбнуться при перечитывании :

```ts
// Трогаем только присутствующие термы (разреженно) вместо прогона по 3000 dims.
for (const [t, c] of counts) {
```

Вместо прогона 3000 дименшнов на каждый тикет, ты трогаешь только пару десятков присутствующих слов. Вот почему это отвечает за меньше 1ms. Та самая невидимая деталь, которая всё меняет в проде, потому что сложность идёт от размера тикета, а не словаря.

`src/logreg.ts:86`, инференс, который укладывается в три строки :

```ts
// бинарник: 1 строка коэфов + сигмоида
const pPos = 1 / (1 + Math.exp(-s));
// мультикласс: скалярное произведение + softmax, argmax
```

Одно скалярное произведение, сигмоида или софтмакс в зависимости от числа классов. Один проход и всё. Ноль сгенерированных токенов, значит ноль сломанного JSON, который потом чинить ретраями и эвристиками парсинга.

Рецепт `train.py` : 300 трейн / 100 тест на воркфлоу, детерминированный сплит (каждый 5-й айтем в тест чтобы убрать временной байас), словарь 3000-6000, коэфы округлены до 1e-4 с нулевой замеренной потерей. Экспорт в JSON `{ vocab, idf, questions }`.

Веса : 20 Кб для invoices (`duplicate` 0.89) до 650 Кб для mail (`bucket` 0.889). Размер, который лезет во фронтенд-бандл.

Деталь, которая меня прибила : на мейле MiniLM жмётся к TF-IDF в +/-0.02. Так что nano шипается как есть. Платить за GPU чтобы сортировать почту, это без меня. А вот agent_trace буксует (`needs_review` 0.59 в nano) : текст обсервебилити бедный, ни одно слово реально не тянет решение.

Фабрика, которая превращает веса в плагин, в `src/plugin.ts:52` :

```ts
export function nanoClassifier(manifest, weights, opts = {}) {
  return definePlugin({ manifest,
    classify: (input) => {
      const r = predict(`${from}${input.state}`, weights, q);
      return { decision: r.decision, confidence: r.confidence, domain: manifest.domain };
    }});
}
```

`decide()` остаётся синхронным для nano, `decideAsync()` открывает ONNX для mini. Два пути, одно простое правило : если тебе нужен async, значит хочешь mini, иначе nano хватает. Легко запомнить когда кодишь, легко дебажить когда ломается.

Чтобы показать, что это не просто теория, вот как выглядит реальное использование :

```ts
import { Sabaki } from "sabaki";
import customerService from "@sabaki-js/customer-service";

const sabaki = new Sabaki().register(customerService);
sabaki.decide({ state: "charged twice, refund please" });
// { decision: "billing", confidence: 0.31, domain: "customer_service" }
```

### Mini, 22 Мб, которые меняют игру на сложных кейсах

У Nano есть пределы, ты видел их на agent_trace чуть выше. MiniLM-L6 подхватывает флаг : один shared-энкодер на весь домен, плюс линейная голова на вопрос. Файн-тюн end-to-end 8-12 эпох, lr 2e-5, на GPU CUDA для обучения (инференс всё равно CPU, это и важно).

Цифры, которые всё решили, замерены на тех же сплитах :
- замороженный энкодер + MLP : 0.65
- полный файн-тюн : 0.68
- дистилляция 400M в замороженные эмбеддинги : попробовали, выкинули, хуже чем gold-лейблы

Экспорт в ONNX через dynamo, точный паритет проверен, потом динамическая квантизация int8 : 90 Мб -> 22 Мб, **-0.004 accuracy** на customer_service. ECE неизменна или лучше. Каждый экспорт перемеряется, иначе оптимизация ничего не значит.

С 1.0.2 веса лежат в пакете (`models/<workflow>-int8/` + экспортированный `modelDir`). Хватает `npm i`, самолётный режим ок. Обновить = опубликовать патч, подписанный через trusted publishing.

Конкретно : `needs_review` прыгает с 0.59 до **0.82**. `disposition` 0.73 -> 0.76. ECE < 0.14 везде, с честным OOD-сомнением (0.2-0.5 на драконах, рецептах и пустых строках). Это сомнение и разрешает агрессивное порогование в проде.

### Generalist, catch-all, который делает Sabaki настоящим System One

Jev и остальные отвечают на всё : любой вопрос, любые опции, заданные в рантайме. Это и есть контракт System One, который сделал Jev вирусным, -- ты задаёшь свои `instructions` + `criteria` со своими опциями, он решает.

Специалисты Sabaki так не умеют. Они знают свои вопросы (`category`, `duplicate`, `bucket`) и больше ничего. Без страховки Sabaki возвращал бы `unknown` как только ты уходишь со скрипта, там где Jev всегда что-то отвечает.

Дженералист это и есть страховка. Кросс-энкодер, который читает вопрос + опцию + state и выдаёт скор, один проход на опцию, софтмакс, argmax. 22.7M MiniLM int8 -- в 6.5x меньше чем 144-151M у банды. Но его работа не скор, а совместимость : с ним в фолбэке `POST /v1/systemone` принимает любой state и любые вопросы, как Jev. Поле `model` говорит, кто реально ответил (`@sabaki-js/mail@1.1.2+mini`, `sabaki-generalist-v1`...), так что на вызывающей стороне ты ничего не меняешь.

И главное, это фолбэк, а не босс. Золотое правило в `decideAsync()` : если выигрывает роутинг специалиста, отвечает он. Дженералист говорит только на `unknown`. Никогда наоборот. Это не даёт среднему дженералисту затоптать хорошего специалиста на его поле.

Лоадер живёт в `src/generalist.ts`, с кэшем по папке чтобы не перезагружать ONNX-сессию на каждый вызов :

```ts
export function loadGeneralist(modelDir: string) {
  // кэш по папке, ONNX-сессия переиспользуется
  // tokenizer.json -> Unigram или wordpiece, автоопределение
  const sess = await ort.InferenceSession.create(
    path.join(modelDir, "generalist.onnx"),
    { intraOpNumThreads: 2 },
  );
}
```

Ты указываешь `SABAKI_GENERALIST_DIR` на папку с `generalist.onnx` + `tokenizer/`, модель swappable. Id берётся из `config.json`, иначе `"sabaki-generalist"`. Кэш на `Map` спасает от перезагрузки сессии на каждый вызов.

Формат входа, это классический кросс-энкодер : вопрос, опция и state склеены с разделителями, по строке на опцию для скоринга :

```ts
const texts = options.map(
  (o) => `${input.question ?? "decision"} [SEP] ${o} [SEP] ${input.state}`,
);
```

Вопрос + опция + state, через `[SEP]`, по строке на опцию. Опции капаны на 8 (`slice(0, 8)`), дефолт `["yes", "no"]` если ты ничего не дал. Дальше режь на вызывающей стороне, -- 8 уже широко для типизированного решения.

Дальше идёт умный батч, та оптимизация, которая выглядит скромно, но делит латентность на число опций. Вместо одного `session.run` на опцию, всё летит одним форвардом :

```ts
// Один батчевый форвард на все опции
// (добито до макс. длины) вместо run на опцию.
const L = Math.max(...encs.map((e) => e.ids.length));
// ids + attention_mask в [options.length, L], паддинг до padId
const out = await sess.run({ input_ids, attention_mask });
const scores = Array.from(out["score"].data).map(Number);
```

Каждый текст кодируется (wordpiece в стиле BERT или unigram SentencePiece по `tokenizer.json`), добивается до макс. длины батча, складывается в тензор `[nb_options, L]`. Один `sess.run`, забираешь скор на опцию. На CPU это всё меняет : 20-36ms вместо 8x этого времени.

Потом софтмакс + argmax, с полными пробами на каждую опцию, ровно в том формате, который популяризовал Jev :

```ts
const pr = softmax(scores);
// bi = индекс макса
const confidence = Math.round(pr[bi] * 1000) / 1000;
const probs = Object.fromEntries(
  options.map((o, i) => [o, Math.round(pr[i] * 1000) / 1000]),
);
```

А деталь, которая делает штуку пригодной в проде, а не демкой, это `abstainAt` :

```ts
if (input.abstainAt !== undefined && confidence < input.abstainAt) {
  return { decision: null, confidence, domain: "generalist", probabilities: probs };
}
```

Opt-in, без abstention по дефолту. Передаёшь `abstainAt: 0.6-0.7` и всё вялое возвращается `null` вместо гесса. Учитывая, что софтмакс выдаёт 1.00 даже когда неправ вне распределения, это не роскошь. GUIDE рекомендует его для любого автономного использования : ниже порога просишь уточнение вместо авторезолва.

В конце вот та же сборка с фолбэк-дженералистом : когда ни один специалист не матчится, подхватывает он вместо возврата `unknown`.

```ts
import { Sabaki, definePlugin, loadGeneralist } from "sabaki";
import mail from "@sabaki-js/mail";

const backend = loadGeneralist(process.env.SABAKI_GENERALIST_DIR!);
const generalist = definePlugin({
  manifest: { name: "@sabaki-js/generalist", domain: "generalist",
    version: "0.1.0", questions: ["decision"], keywords: [] },
  classify: (input) => backend.decide(input),
});

const sabaki = new Sabaki().register(mail).setFallback(generalist);

await sabaki.decideAsync({
  state: "le client dit que l'app a supprimé ses données",
  question: "c'est urgent ?",
  options: ["yes", "no"],
  abstainAt: 0.65,
});
// специалист mail если роутинг сматчился, иначе generalist как catch-all в стиле Jev
```

Генерации дженералиста, все замерены одинаково на PhishNChips (2000 писем) и на тесте typed-decisions чтобы сравнивать сравнимое :
- v4 : 0.29 тест, R=0.026 фишинг. В помойку, отвечал мимо.
- A (22M 80k) : 0.546, R=0.406. Уже начинает на что-то походить.
- mini v1 на проде : **0.536, R=0.616**. Это та, что крутится на сайте. Вменяемый recall фишинга, средний тест.
- B (144M scratch) : 0.568, R=0.062. Больше, чуть лучше в тесте, никакой в фишинге.

144M со скретча, который не трансферит лучше, хорошо остудил меня насчёт "накинуть параметров чтобы обобщить". При равной задаче жирный стоит дороже, а гадает не лучше. Даже как catch-all мелкий тащит. И он остаётся EN-only (`all-MiniLM-L6-v2`), роутинг EN, FR вне распределения. Для FR иди через специалиста, обученного на нём, а не через дженералиста.

## Doom, единственный тест, который мне реально важен

doomLaya, это Laya и Jev, которые играют во FreeDoom по-настоящему. Модель выбирает `command / target / weapon`, экзекьютор ведёт по A*, открывает двери, целится, кликает. Телеметрия по тикам, видосы, SHA ранов. Я туда контрибьючу, так что говорю не про лидерборд, вычитанный издалека.

v0.1.0, MAP01 seed 48, skill 3, 35 тиков/с, тот же экзекьютор :

| Модель | Результат | p50 HTTP | Цена API |
|---|---|---|---|
| Laya stock | провал 180s | 106ms | $0 |
| Laya v3 адаптированная | выход 61.43s | 108ms | $0 |
| Jev 1.13 | выход 68.97s | 357ms | $0.0046 |

Два чистых выхода, без смертей, Laya по пути подбирает шотган потому что экзекьютор сам рулит подбор. Честно : Laya v3 обучена на Doom, Jev нет. Один сид, одна карта, это ничего общего не доказывает. README проекта так и говорит чёрным по белому, и это делает ему честь, что результат не oversellится.

Со стороны Sabaki ([plugin-doom](https://github.com/sabaki-js/plugin-doom)) : ViZDoom на Python, который дёргает JS-сервер каждый тик. Nano ~18k req/s, mini ~71 req/s на одном потоке i5. Тик 35Hz проходит с запасом, даже на среднем ноуте.

С компасом выхода mini проходит MAP01 в 2-4 ранах из 6, nano 0/6. Логично : текст теряет spatial, состояния doomLaya упираются где-то в 0.57 что на MiniLM, что на ModernBERT-base. Когда пространственной инфы нет, никакой текстовый классификатор её не выдумает.

Соседи пересняли матч на равных данных : [doomgemma](https://github.com/dexmac221/doomgemma) вешает LoRA на 27 мин на RTX 4070 и доводит Gemma 4 E2B до уровня Laya v3 в игре (6/6 vs 6/6) и выше в изолированных решениях. При равном размере декодер идёт так же быстро как Laya (270M : 22ms vs 23ms). При равном результате Laya остаётся ~3x быстрее потому что добирается туда меньшей моделью.

Мой вывод : обучение на задаче важнее архитектуры. Мелкий специалист, обученный под задачу, бьёт жирного дженералиста, который видит её впервые. Ровно ставка Sabaki. Следующая бумага, *System Switch* ([arXiv:2610.09683](https://arxiv.org/abs/2610.09683)), дожимает логику до конца : быстрая мелкая модель играет, жирный рассуждающий подхватывает когда открывается gate. Sabaki pre-triage (`automate > 0.85 иначе эскалация`), применённый к игре.

## Чем пожертвовали

Каждая отсутствующая фича оплачивает другую, таковы правила когда целишься в CPU. Честный список, как для Bareiron где каждая строка C была трейдоффом :

**Sabaki ничего не рассказывает.** Он выбирает между опциями, которые ты ему даёшь, с пробой. За объяснением, саммари, свободным текстом иди к LLM.

**Французский остаётся вне распределения для дженералиста.** Роутинг EN (`all-MiniLM-L6-v2`), зонд 1/4 FR vs 3/4 EN на похожих кейсах. Мейл-плагин приехал из в основном FR-ящика, но анонимизированного : 0 PII, -0.024 accuracy за словарь без персональных термов. Анонимизация стоит денег, но это было non negotiable.

**Софтмакс слишком уверен когда выходит из своей зоны.** Ложняки с 1.00 видали, да. Отсюда рекомендованный pre-triage в GUIDE : `abstainAt: 0.6-0.7` чтобы отдавать `null` под порогом, потом gate `confidence > 0.85` на автомат, человек на остальное. Замеренный референс : recall фишинга 0.62 при precision 0.87. Хватает чтобы разрезать очередь пополам, не хватает чтобы уволить ревьюеров.

**Nano буксует на трейсах агентов.** 0.34 до 0.59 в зависимости от вопроса. Mini поднимает `needs_review` до 0.82, но `risk / urgency / action` остаются тяжёлыми. Текст обсервебилити просто беден на лексические сигналы.

**Doom в тексте упирается.** Где-то в 0.57, что MiniLM, что ModernBERT-base. Пока сидишь на тексте без пикселей, MAP02 тебя стопает. Вменяемый путь к реально играющему -- vision + RL (tiny-doom-defender, 1.1M параметров с пикселей), а не лучший текстовый классификатор.

**Бенчмарк дрейфует батчами.** typed-decisions сгенерирован пачками, временной сплит по факту сплит батчей. `drift_tool.py` выдаёт 0.82 на customer_service, 0.67 на agent_trace (0.5 = неразличимо). Замеренное следствие : опубликованные веса дают 0.733 в миксе vs 0.61 на официальном сплите. Так что официальная цифра консервативна. Калибрация Platt / temperature+bias не трансферится между батчами, поэтому шипаем только temperature scaling, откалиброванный на свежих батчах. Домашнее правило : сначала `drift_tool.py`, warn выше 0.6, block выше 0.8. Никто другой это не публикует, а должны бы все.

## Финальный результат, с цифрами на руках

С одной стороны ноутбучный i5, с другой API со счётчиком за вызов. Вот что каждый режим даёт конкретно :

- nano : <1ms, ~18k req/s, 20-650 Кб, 0 зависимостей
- mini : ~20ms, ~71 req/s, 22 Мб int8, onnxruntime опционально
- generalist : 20-36ms, 22.7M, самый мелкий опен-дженералист что я знаю

Несколько доменов загружены : ~0.5 Гб RAM в lazy-load по домену вместо ~2 Гб за всё. Детерминированно : 100/100 одинаковых инпутов дают одинаковый аутпут. Пороги на вопрос, gate на `confidence`, `unknown` когда ничего не матчится.

На Bareiron 3+ игроков тормозили потому что каждый игрок стоил чанк в 200ms. Тут 3+ домена проходят не напрягаясь, потому что каждый эксперт крошечный и грузится по требованию вместо загрузки всего сразу. Та же философия "мелкого, которого хватает", на другом железе.

## Философия

p2r3 говорил : *"Мне просто нравится идея, что эта крошечная чипуха за 1 бакс может крутить что-то настолько продвинутое как Minecraft."*

Тот же вайб тут : мне нравится идея, что 20 Кб JSON и сотня строк TS заменяют вызов GPU чтобы выбрать лейбл. Это очевидно заменяет не всё, не надо гнать. Это заменяет душный кейс где тебе нужен лейбл за миллисекунды, локально, с уверенностью, которую можно вменяемо пороговать вместо скрещенных пальцев.

Трейдоффы, чёрным по белому :
- энкодер -> подсчёт слов : минус 7 пунктов, латентность делить на 1000, инфры ноль
- жирная уникальная модель -> npm-плагины : gate грубее, опсы бесконечно проще
- генерация -> типизированное решение : конец ломающемуся парсингу и выдуманным опциям
- сырая уверенность -> pre-triage : сначала abstain, автоматизация выше 0.85, человек на остальное

**3 вещи для запоминания :**

1. **7 пунктов меньше, в 1000x быстрее** -- 0.61/0.69 vs 0.75-0.80, но <1ms/20ms CPU в офлайне против 25s CPU или платного API. Скор без его цены ничего не значит.
2. **Простой роутер + отдельные эксперты** -- `hits / sqrt(keywords)`, threshold, `unknown`. Каждый плагин тренируется, версионируется и шипается отдельно. На мейле TF-IDF жмётся к MiniLM : GPU тут ни к чему.
3. **Offline-first с честной калибровкой** -- `npm i`, веса в комплекте, 0 GPU, ECE < 0.14, abstain, drift tool. Единственный стек из сравнения, который держит игровой цикл на 35Hz без GPU.

Если проект интересен, всё в MIT на [github.com/sabaki-js](https://github.com/sabaki-js). Академическая версия с замерами и bibtex, это [препринт v1](/assets/paper/sabaki-organizational-moe-typed-decisions.pdf). А если хочешь увидеть Голиафа в Doom вживую, тебе в [azalio/doomLaya](https://github.com/azalio/doomLaya) xD
