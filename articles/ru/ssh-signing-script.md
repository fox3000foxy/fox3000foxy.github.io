# Скрипт SSH-подписи коммитов -- объяснение

Эта статья разбирает скрипт `setup-ssh-signing.sh`, который я опубликовал в [Gist](https://gist.github.com/fox3000foxy/95500d129cd4bf5c173c323d2492569a). Посмотрим, что делает каждая часть, как он делает локальную SSH-подпись для репозитория совершенно безболезненной и, да, зачем я вообще его писал (спойлер : я просто хотел, чтобы мои коммиты выглядели **круто**).

## Мотивация

Я всегда любил ковырять свой Git-воркфлоу, и после того как увидел людей с маленькими бейджами «Verified» рядом с коммитами, подумал : а чем я хуже? Встроенная подпись GPG тяжёлая и глобальная, так что я в итоге написал маленький хелпер, который :

- создаёт отдельный SSH-ключ для подписи,
- настраивает только текущий репозиторий,
- при желании переписывает историю, чтобы подписать старые коммиты,
- и позволяет переносить ключ между машинами.

Честно, нужда была в основном про тщеславие. Мои личные проекты не требуют никакой подписи, но зелёный бейдж «Verified» на коммите даёт свой маленький эффект, а писать этот скрипт на шелле было прям в кайф.

> Подписывать свои коммиты это немного как надеть кожаную куртку на код-ревью -- совершенно бесполезно, но чувствуешь себя хакером.

## Что делает скрипт

Скрипт это один файл Bash с `set -euo pipefail` наверху, чтобы останавливать выполнение при первой же ошибке. Вот кратко, что он делает :

1. **Создать или импортировать ключ подписи**
   Ключи попадают в `.git-signing/` в папке, где ты запускаешь скрипт.
2. **Настроить Git локально**
   Он ставит `gpg.format=ssh`, `user.signingkey`, `commit.gpgsign=true`, `tag.gpgSign=true` и `allowedSignersFile`, указывающий на публичный ключ.
3. **Управлять ключами между машинами**
   Благодаря `--export-keys` / `--import-keys` ты можешь переносить приватный ключ с одного компа на другой, не трогая глобальную конфигурацию.
4. **Опциональное переписывание истории** (`--resign-all`)
   Переписывает все коммиты всех веток и тегов (или только те, что не в `upstream`, для форков) и переподписывает их с `-S`, не трогая других авторов.
5. **Утилитарные флаги**
   `--autostash`, `--autopush`, `--commit-date`, `--yes` для неинтерактивного режима и т.д.
6. **Определение форка и проверки безопасности**
   Он определяет remote `upstream`, предупреждает перед переписыванием истории, проверяет нужные инструменты (`git`, `ssh-keygen`, `zip/unzip`), следит за правильными правами и даже создаёт защищённую копию ключа, если права файловой системы слишком открытые.

Скрипт идемпотентный : запуск дважды не пересоздаёт твой ключ и не затирает существующую конфигурацию.

## Разбор по шагам

Вот несколько ключевых отрывков кода с пояснениями.

```bash
#!/usr/bin/env bash
set -euo pipefail

# Настройка подписи коммитов по SSH контролируемым, локальным для репозитория способом.
# - Файлы ключей создаются в каталоге, где запускается этот скрипт.
# - Конфигурация Git пишется локально только для текущего репозитория.
```

Шапка задаёт безопасность и документирует цель. Следующий кусок парсит опции CLI (`--name`, `--email`, `--repo` и т.д.) циклом `while [[ $# -gt 0 ]]; do case … esac done`. Обязательные поля идентичности проверяются позже :

```bash
if [[ -z "$NAME" || -z "$EMAIL" ]]; then
  echo "Error: missing identity. Provide --name and --email." >&2
  exit 1
fi
```

Генерация ключа происходит в `$LAUNCH_DIR/.git-signing`. Если ключ уже есть, скрипт оставляет его как есть ; `--import-keys` позволяет заполнить папку из ZIP.

```bash
mkdir -p "$KEY_DIR"

if [[ -n "$IMPORT_ZIP_PATH" ]]; then
  import_keys_from_zip "$IMPORT_ZIP_PATH"
fi

if [[ ! -f "$KEY_PATH" ]]; then
  ssh-keygen -t ed25519 -N "" -C "$EMAIL signing key" -f "$KEY_PATH" >/dev/null
  echo "Generated signing key: $KEY_PATH"
else
  echo "Signing key already exists: $KEY_PATH"
fi
```

После проверки, что приватный ключ usable (`ssh-keygen -Y sign …`), скрипт пишет файл `allowed_signers` с публичным ключом и ставит локальную конфигурацию Git :

```bash
git -C "$REPO_DIR" config --local gpg.format ssh
git -C "$REPO_DIR" config --local user.signingkey "$RUNTIME_KEY_PATH"
git -C "$REPO_DIR" config --local gpg.ssh.allowedSignersFile "$ALLOWED_SIGNERS"
git -C "$REPO_DIR" config --local commit.gpgsign true
git -C "$REPO_DIR" config --local tag.gpgSign true
```

Если просишь переписать историю через `--resign-all`, скрипт строит команду `git filter-branch`, которая переподписывает подходящие коммиты с `-S`. Он уважает состояние форка, при желании пропуская коммиты, уже присутствующие в `upstream`.

Финальный результат показывает публичный ключ и инструкции, как добавить его в секцию **Signing Key** на GitHub, с рецептом проверки.

## Зачем подписывать коммиты?

Сейчас признаюсь, что мне это было не нужно. Мои репозитории не требуют никакого подтверждения происхождения публикуемого, и я не использую подписанные теги для релизов. «Зачем» такое :

- потому что мог,
- потому что это красиво выглядит (видел бейдж?),
- потому что это дало повод поэкспериментировать с `git filter-branch` и шеллом,
- и потому что это очередное «сделал сам» для блога.

Короче, это был просто понт, но именно это мне и нравится, когда я ковыряю свои инструменты.

## Примеры использования

```bash
# первичная настройка в текущем репозитории
chmod +x ./setup-ssh-signing.sh
./setup-ssh-signing.sh --name "Your Name" \
                       --email "you@example.com"

# экспортировать ключи на другую машину
./setup-ssh-signing.sh --export-keys ./my-signing-keys.zip

# импортировать ключи на второй машине
./setup-ssh-signing.sh --import-keys ./my-signing-keys.zip --repo ./my-repo \
                       --name "Your Name" --email "you@example.com"

# переписать историю и запушить
./setup-ssh-signing.sh --repo ./my-repo --name "Your Name" --email "you@example.com" \
                       --resign-all --autostash --autopush --yes
```

## Последние мысли

Скрипт остаётся компактной утилитой, но в нём есть несколько принципов, за которые я стою :

- держать криптографические ключи локально и на репозиторий,
- никогда не трогать глобальную конфигурацию, если ты сам не попросишь,
- давать простой импорт/экспорт и переписывание истории,
- и документировать весь процесс в статье блога, чтобы остался переиспользуемый след.

Если захочется добавить подписи к своим коммитам, попробуй! А если ты тут просто ради стиля, тоже норм. 😎
