## 勾配降下だけの問題

取引アルゴリズム用DQNエージェントを古典的な勾配降下で訓練すると、言うのは簡単で解くのは難しい問題が出る。勾配は_1つ_のネットを_1つ_の極小へ、_1つ_の市場ウィンドウ上で最適化する。この極小が違う市場レジームに一般化する保証はなく、訓練ループ内のどこにも多様性への押しはない。違うシードから始めた2つのrunは、同じ死角を持つほぼ同一戦略に収束することが多い。

私が探った答え：勾配降下を遺伝的アルゴリズムに置き換える（というか重ねる）ことだ。エージェント1つを訓練する代わり、エージェント集団を進化させる。各個体はアーキテクチャとハイパーパラメータをエンコードしたゲノムを持ち、勾配は各個体の生涯内で磨きをかけ続ける間、自然選択に選別させる。

このrunnerは集中的な作業セッション1回で4バージョンを経た。各バージョンが前の構造的欠陥を直した。

## v1：素朴版と、なぜ足りなかったか

初版は基本的GAの期待通りだった。ゲノム集団、適応度関数、選択、交叉、突然変異、次世代。各ゲノムはネットのトポロジー（層数、幅）、DQNハイパーパラメータ（学習率、epsilon減衰、リプレイバッファサイズ）、いくつかのアーキテクチャ選択（どのデータソースを食うか、埋め込みサイズ）をエンコードした。

主な欠陥：適応度が訓練と同じデータで計算されてた。エージェントは文字通り市場ウィンドウを暗記して、一般化戦略を何も学ばずに優秀なスコアを取れた。古典的過学習だが、遺伝選択で増幅される。GAはこの抜け穴をいちばん突く個体を積極的に選ぶからだ。

## v2：訓練と評価を分ける

明らかな修正はフェーズ分離だった。各ゲノムは市場ウィンドウで訓練して、訓練で見たことのない違うウィンドウで評価する。適応度に数えるのは評価性能だけだ。

この変更だけで集団の平均適応度は下がった。v1で性能に見えたものの相当部分が純粋な暗記だった証拠だ。見るのは痛い。でもまさに欲しい信号だ。膨らんだ嘘スコアより低くて正直なスコアの方がいい。

## v3：NSGA-IIと多目的適応度へ

適応度スコア1つ（たとえば収益）の最適化は、その1つの数字を最大化する極端リスクのエージェントへ機械的に向かう。解はNSGA-II（Non-dominated Sorting Genetic Algorithm II）への移行だった。収益、最大ドローダウン、シャープレシオ、ウィンドウ間安定性を、恣意的な重み付き合計に潰さず同時最適化する。

NSGA-IIはパレートフロントを作る。ある目的の改善が他を劣化させずに不可能なゲノム集合だ。事前選択の重み付けで収益とリスクの妥協1つを強制する代わり、妥協の境界全体を残して、最終選択は開けたままにする。

```
function nonDominatedSort(population: Genome[]): Genome[][] {
  const fronts: Genome[][] = [[]];
  for (const p of population) {
    p.dominationCount = 0;
    p.dominatedSet = [];
    for (const q of population) {
      if (dominates(p, q)) p.dominatedSet.push(q);
      else if (dominates(q, p)) p.dominationCount++;
    }
    if (p.dominationCount === 0) {
      p.rank = 0;
      fronts[0].push(p);
    }
  }
  // ... 反復除去で後続フロントを構築
  return fronts;
}
```

v3の2つ目の追加は**永続パレートアーカイブ**だ。これがないと、世代12で見つけた良いゲノムが、交叉の偶然で再生産されず世代15で消えることがある。置き換えたもの全部より優れてたのにね。アーカイブは現行集団と関係なく、全世代を通じて出会った非劣化個体集合を保つ。

## v4：ラマルク進化と環境多様性

v3には構造的死角があった。ゲノムはアーキテクチャを記述するのに、訓練で学んだ重みは新世代ごとに消えた。優秀な両親の交叉で生まれた子はアーキテクチャを受け継ぐのに、ゼロから学び直しだった。両親を優秀にした重みの痕跡はなかった。

v4は**ラマルク進化**を入れる。訓練済み重みは訓練後にゲノムへ再注入されて、子孫へ（突然変異付きで）伝えられる。自覚的な生物学的異端だ。ラマルクは生物には間違ってた。獲得形質の遺伝は生物学に存在しない。でも数値GAが賢くごまかすのを止めるものは何もない。ここでは獲得物の伝達が収束を根本から速める。各世代がランダム重みじゃなく情報ある初期点から始めるからね。

この版の他3つの構造変更：

*   **環境多様性**：各ゲノムは単一市場ウィンドウじゃなく複数で評価される。違うレジーム（上昇、下降、レンジ）から引く。1つのウィンドウで秀でて他で崩れるエージェントはパレートフロントを支配できなくなる。
    
*   **FLOPs複雑性による正則化**：ネット計算コスト（FLOPs）がNSGA-IIの独立目的になる。性能利得に見合わないのに brute capacity だけで巨大アーキテクチャに進化が収束するのを防ぐ。
    
*   分離された`RLBackend`**インターフェース**：GAはDQN詳細を知らなくなる。ゲノムを扱って抽象インターフェース越しに`train()`や`evaluate()`を呼ぶ。理論上、進化エンジンに触らず別のRLアルゴリズムを繋げる。

```
interface RLBackend {
  train(genome: Genome, window: MarketWindow): Promise<TrainedWeights>;
  evaluate(genome: Genome, weights: TrainedWeights, window: MarketWindow): Promise<FitnessVector>;
}
```

最後の技術点：評価は**有界非同期並行**になった。逐次ループじゃなくN並列評価プールで、GPUやCPU資源を飽和させない明示上限付きだ。

## v4がv3に対して実際に直すこと

v3の欠陥 v4の修正 世代ごとに重み消失 訓練済み重みのラマルク再注入 単一市場ウィンドウへの過学習 複数ウィンドウ評価、レジーム多様 制約なしに肥大するアーキテクチャ FLOPsを明示パレート目的に DQN詳細と結合したGA 抽象`RLBackend`インターフェース 遅い逐次評価 有界async並行

v4は「グラウンディング」APIバグも10個直した。GAコードが`TradingAgent`向けインターフェースを仮定してて、実際の実装と完全一致しなかったケースだ。こういうバグは本物のエージェントソースコードと突き合わせないと見えない。v4は実ファイルと行ごとに向き合って初めて検証された。

## 進化と勾配を混ぜる理由、択一じゃない理由

純RLかNEAT式純進化でいいじゃないかと思うかもしれない。答えは一文だ。勾配は局所磨きが得意だ（近い最適へ連続重みを調整する）。進化は大域探索が得意だ（離散探索空間が微分不可能で勾配が届かないアーキテクチャやハイパーパラメータ組み合わせを発見する）。片方なしで使うのは2つの探索形の片方を捨てることだ。

代償は工学的複雑さだ。4バージョンは贅沢じゃなかった。GAとRLのループが自滅（過学習、良個体消失、獲得重み消失）をやめるのに必要な反復回数だった。でも結果は、単なるハイパーパラメータのグリッドサーチよりずっと広い設計空間を探るシステムになった。各評価候補には勾配の局所効率を残したままでね。

## 次の段階

この単層進化アーキテクチャ（DQNゲノムの平坦集団）は、カバー資産数が増えると限界に来る。3層階層アーキテクチャ（Asset AnalystsからSector ManagersからPortfolio Allocatorへ）への移行を動機付けた。各層でGAが独立動作する。でもそれは別の記事の話だ。
