## Проблема с одним градиентным спуском

Обучать DQN-агента для алгоритмического трейдинга классическим градиентным спуском ставит проблему, простую в формулировке и трудную в решении : градиент оптимизирует _одну_ сеть к _одному_ локальному минимуму на _одном_ окне рынка. Ничто не гарантирует, что этот минимум обобщится на другой режим рынка, и ничто в цикле обучения не толкает к разнообразию ; два запуска с разных сидов часто сходятся к почти одинаковым стратегиям с одинаковыми слепыми зонами.

Ответ, который я исследовал : заменить (точнее, надстроить) градиентный спуск генетическим алгоритмом. Вместо обучения одного агента развиваем популяцию агентов ; каждый это геном, кодирующий архитектуру и гиперпараметры ; а естественный отбор делает сортировку, пока градиент продолжает доводить каждого индивида внутри его собственной жизни.

Этот раннер прошёл четыре версии за одну интенсивную рабочую сессию. Каждая исправила структурный дефект предыдущей.

## v1 : наивная версия, и почему её не хватало

Первая версия делала то, чего ждёшь от базового ГА : популяция геномов, функция фитнеса, отбор, скрещивание, мутация, следующее поколение. Каждый геном кодировал топологию сети (число слоёв, ширину), гиперпараметры DQN (learning rate, затухание эпсилон, размер replay-буфера) и несколько архитектурных выборов (какие источники данных потреблять, какой размер эмбеддинга).

Главный дефект : фитнес считался на тех же данных, что и обучение. Агент мог буквально запомнить окно рынка и получить отличный балл, не выучив обобщаемой стратегии. Классическое переобучение, но усиленное генетическим отбором ; ГА активно отбирает индивидов, лучше всех эксплуатирующих эту лазейку.

## v2 : разделить обучение и оценку

Очевидным исправлением было разделить фазы : каждый геном обучается на одном окне рынка, а оценивается на другом, никогда не виденном при обучении. Для фитнеса считается только результат оценки.

Одно это изменение уронило средний фитнес популяции ; признак того, что добрая часть того, что выглядело результатом в v1, была чистым запоминанием. Больно смотреть, но это ровно тот сигнал, что нужен : более низкий, но честный балл лучше накачанного и обманчивого.

## v3 : переход на NSGA-II и многоцелевой фитнес

Оптимизация одного балла фитнеса (скажем, доходности) механически толкает к агентам, которые идут на крайний риск ради максимизации этой единственной цифры. Решением стал переход на NSGA-II (Non-dominated Sorting Genetic Algorithm II), который оптимизирует одновременно несколько целей, не сводя их к произвольной взвешенной сумме : доходность, максимальную просадку, коэффициент Шарпа, стабильность между окнами.

NSGA-II строит фронт Парето : множество геномов, для которых никакое улучшение по одной цели невозможно без ухудшения другой. Вместо того чтобы навязывать единственный компромисс между доходностью и риском через заранее выбранное взвешивание, мы сохраняем всю границу компромиссов и оставляем финальный выбор открытым.

```
function nonDominatedSort(population: Genome[]): Genome[][] {
  const fronts: Genome[][] = [[]];
  for (const p of population) {
    p.dominationCount = 0;
    p.dominatedSet = [];
    for (const q of population) {
      if (dominates(p, q)) p.dominatedSet.push(q);
      else if (dominates(q, p)) p.dominationCount++;
    }
    if (p.dominationCount === 0) {
      p.rank = 0;
      fronts[0].push(p);
    }
  }
  // ... построение следующих фронтов итеративным удалением
  return fronts;
}
```

Второй добавкой v3 стал **постоянный архив Парето**. Без него хороший геном, найденный в поколении 12, может исчезнуть к поколению 15, если случай скрещивания его не воспроизведёт ; даже если он оставался лучше всего, что его заменило. Архив хранит сквозь все поколения множество никогда не встречавшихся недоминируемых индивидов независимо от текущей популяции.

## v4 : ламарковская эволюция и разнообразие сред

У v3 было структурное слепое пятно : геном описывал архитектуру, но выученные при обучении веса исчезали с каждым новым поколением. Потомок, рождённый скрещиванием двух хороших родителей, наследовал их архитектуру, но должен был переучиваться с нуля ; никакого следа весов, сделавших его родителей результативными.

v4 вводит **ламарковскую эволюцию** : обученные веса возвращаются в геном после обучения и передаются (с мутацией) потомству. Это осознанная биологическая ересь ; Ламарк ошибался насчёт живых организмов, наследования приобретённых признаков в биологии не существует ; но ничто не мешает числовому ГА жульничать с умом : здесь передача приобретённого радикально ускоряет сходимость, потому что каждое поколение стартует с уже информированной точки инициализации, а не со случайных весов.

Три других структурных изменения в этой версии :

*   **Разнообразие сред** : каждый геном больше не оценивается на одном окне рынка, а на нескольких, взятых из разных режимов (бычий, медвежий, флэт). Агент, который блистает на одном окне и рушится на другом, больше не может доминировать на фронте Парето.

*   **Регуляризация сложностью FLOPs** : вычислительная стоимость сети (в FLOPs) становится отдельной целью в NSGA-II. Это не даёт эволюции сходиться к массивным архитектурам просто потому, что у них больше грубой ёмкости, без оправданного приростом результата.

*   **Отвязанный интерфейс** `RLBackend` : ГА больше не знает деталей DQN. Он оперирует геномом и вызывает `train()` / `evaluate()` через абстрактный интерфейс, что в теории позволяет подключить другой RL-алгоритм, не трогая эволюционный движок.


```
interface RLBackend {
  train(genome: Genome, window: MarketWindow): Promise<TrainedWeights>;
  evaluate(genome: Genome, weights: TrainedWeights, window: MarketWindow): Promise<FitnessVector>;
}
```

Последний технический момент : оценка переведена на **ограниченный асинхронный параллелизм** ; пул из N параллельных оценок вместо последовательного цикла, с явным лимитом, чтобы не насыщать доступные ресурсы GPU/CPU.

## Почему смешивать эволюцию и градиент, а не выбрать одно

Можно спросить, почему бы просто не делать чистый RL или чистую эволюцию в духе NEAT. Ответ укладывается в одну фразу : градиент отлично доводит локально (подстраивает непрерывные веса к близкому оптимуму), эволюция отлично исследует глобально (открывает архитектуры и комбинации гиперпараметров, которых никакой градиент не достигнет, потому что дискретное пространство поиска недифференцируемо). Использовать одно без другого значит лишить себя одной из двух форм исследования.

Плата это инженерная сложность ; четыре версии были не роскошью, а числом итераций, нужным, чтобы цикл GA + RL перестал саботировать сам себя (переобучение, потеря хороших индивидов, потеря приобретённых весов). Но итог это система, исследующая куда более широкое пространство дизайна, чем простой grid search гиперпараметров, сохраняя при этом локальную эффективность градиента для каждого оцениваемого кандидата.

## Следующий шаг

Эта одноуровневая эволюционная архитектура (плоская популяция геномов DQN) упирается в пределы, когда растёт число покрываемых активов. Именно это подтолкнуло к трёхуровневой иерархической архитектуре (Asset Analysts → Sector Managers → Portfolio Allocator) с ГА, работающим независимо на каждом уровне... но это уже тема другой статьи.
