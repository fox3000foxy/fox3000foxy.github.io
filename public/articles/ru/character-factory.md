# Построить character-factory : аватары с генетической системой

Мне нужны были тысячи правдоподобных и разных аватаров для [Kurekuta](https://github.com/fox3000foxy/kurekuta/) -- приватного проекта карточной игры, где каждая карта содержит "ДНК" персонажа, которую движок рендера превращает в портрет. Купить готовый пак было бы видно. Генерировать аватары DiceBear с сидом на персонажа давало ерунду : карта с японской вселенной могла получить скандинавскую блондинку, а двое "брата с сестрой" выглядели незнакомцами.

Поэтому я написал [character-factory](https://github.com/fox3000foxy/character-factory) -- модуль TypeScript поверх коллекции Lorelei от DiceBear, который даёт три возможности, которых нет у одного DiceBear : **согласованные демографические профили**, **маленький движок генетики** и **удобный текучий builder** для использования из игрового цикла.

## Что это делает

Самый маленький полезный сниппет :

```ts
import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // взвешенный этнос → согласованные кожа/волосы/стрижка/борода
  .setMood(Mood.Happy)
  .buildSvg();
```

Эта простая цепочка тянет этнос, взвешенный по демографии Японии, подбирает сочетающиеся тон кожи и цвет волос, выбирает стрижку из нужной гендерной подгруппы, затем фиксирует глаза/брови/рот в "радостном" режиме. Результат выходит в SVG или, с установленным `sharp`, в PNG любого размера.

Персонаж это просто объект `CharacterConfig` -- лицо, волосы, аксессуары, подача. Builder меняет его внутри, а ты можешь экспортировать в JSON, base64 или файл, а потом загрузить обратно один в один. Для Kurekuta это критично : карта хранит конфиг, а не отрендеренную картинку. Так арт всегда воспроизводим, а размер карты остаётся крошечным.

## Согласованные демографические профили, а не случайный пиксель

Опции DiceBear это равномерные селекторы. Передай `["#ffdbb4", "#2c1b18"]` для цвета кожи, и получишь то или другое с равной вероятностью -- ок для логотипа, бесполезно для "дай мне персонажа из Бразилии".

`character-factory` везёт пайплайн страна → этнос → черты :

```ts
// Что лежит в модуле :
ethnicitiesByCountry[Country.Brazil] = [
  { ethnicity: Ethnicity.WestEuropean,  weight: 35 },
  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },
  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...
];

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {
  skinColors: [
    { color: SkinColor.Light,  weight: 35 },
    { color: SkinColor.Warm,   weight: 40 },
    { color: SkinColor.Medium, weight: 20 },
    // ...
  ],
  hairColors: [/* в основном чёрный/тёмно-русый, никакого блонда */],
  hairCuts:   { male: [...], female: [...] },
  beardProbability: 0.15,
};
```

Каждый слой это взвешенный розыгрыш. Веса не социологическая диссертация -- это эвристика, которая не даёт "приехавшему из Японии" получить рыжий, а "приехавшему из Швеции" получить смоляной чёрный. Весь пайплайн сводится к одному вызову : `setCountry(country)` или `randomizeFromCountry(country, gender?)`.

## Маленький движок генетики

Функция, с которой я развлекся сильнее всего : `projectChild`. Две фабрики могут произвести ребёнка, чьи черты наследуются с приблизительной биологической доминантностью :

```ts
const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());
```

Под капотом это намеренно крошечная модель. Каждый родитель несёт генотип из 2 аллелей, по одному с каждой стороны, скомбинированных в доминантный или рецессивный :

```ts
function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}
```

Черты с настоящей осью доминантности (кожа, глаза, волосы) разрешаются явным упорядоченным списком -- тёмное доминирует над светлым, карие/чёрные глаза доминируют над голубыми, смоляной чёрный доминирует над блондом :

```ts
const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // самый рецессивный
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // самый доминантный
] as const;
```

`resolveByRank` находит индекс каждого родителя, берёт больший при "доминантной" комбинации аллелей и меньший при "рецессивной". Фэнтезийных цветов (пастельный розовый, сирень) в порядке нет -- они идут на монетку 50/50, и это правильное поведение : они не биологические, так что доминантность бессмысленна.

Веснушки моделируют MC1R : 75 %, если они у обоих родителей, 25 %, если носитель один, 0 %, если ни у кого. Борода связана с SRY : убирается, если ребёнок девочка, иначе наследуется от родителя, у которого была. Стрижка вообще не биология -- это культурный выбор, так что ребёнок тянет из собственного гендерного пула, по возможности сохраняя текстуру.

Ничего из этого не генетика уровня публикации. Это слой ощущений : дети выглядят как правдоподобная смесь родителей, а не как среднее двух незнакомцев.

## Менее гламурные инженерные части, которые сыграли

Несколько малозаметных деталей, заслуживших место в диффе :

**Более безопасный `pick`.** Оригинал возвращал `undefined`, приведённый к `T`, на пустом массиве. Со `strict` + `noUncheckedIndexedAccess` в TypeScript это ложь с подписью компилятора. Новая версия бросает `RangeError` -- ловится сразу в месте вызова вместо `undefined`-пропсов тремя уровнями ниже.

**`deepMerge`, не портящий массивы.** Старая рекурсия включалась, как только исходное значение было объектом, даже если цель была `null` или массивом. `merge({tags: ["a"]}, {tags: ["b"]})` давал `{tags: {0: "b"}}`. Новая версия рекурсирует, только когда обе стороны простые объекты.

**Параллельный батч-рендер.** `batchFactory` рендерил PNG в сериализованном цикле -- экспорт 1000 карт занимал вечность. Теперь это пул воркеров с настраиваемым параллелизмом (4 по умолчанию), сохраняющий порядок результатов записью в заранее размеренный массив :

```ts
const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // рендер и сохранение
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));
```

На экспорте 1000 персонажей это превратило перерыв на кофе в "уже всё?".

**Сообщение об ошибке `sharp`, которое что-то говорит.** `buildPng` импортирует `sharp` лениво, потому что это опциональная зависимость, которую не хочется навязывать SVG-only пользователям. Старый catch глотал настоящую ошибку и всегда говорил "sharp is required." Если реальным сбоем был конфликт версий или проблема нативных биндингов, ты тратил десять минут на переустановку уже установленного пакета. Новая версия всё равно просит установить, но включает нижележащую ошибку.

## Дальше

Модуль в версии 1.1.1 в [репозитории character-factory](https://github.com/fox3000foxy/character-factory). Генетический движок идеальное место продолжать итерировать -- тестового набора пока нет, так что инварианты согласованности ("бразильский персонаж с восточноазиатским происхождением никогда не получит смоляные глаза с платиновыми волосами") держатся только на весах. Добавить `bun test` или `vitest` и написать тест согласованности, гоняющий десять тысяч `randomizeFromCountry` на страну, это следующий шаг.

Сама Kurekuta пока приватна, но каждая карта, что ты однажды в ней увидишь, это лишь blob `CharacterConfig` и один `buildPng()` от существования.
