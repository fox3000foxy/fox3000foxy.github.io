Building character-factory: avatars with a genetics system

I needed thousands of believable, distinct avatars for Kurekuta -- a private card game project where each card holds a character "DNA" blob that the render engine turns into a portrait. Buying a ready-made pack would have looked off. Generating DiceBear avatars seeded per character gave nonsense: a card with a Japanese setting could land on a Scandinavian blonde, and two "siblings" looked like strangers.

So I wrote character-factory -- a TypeScript module on top of the DiceBear Lorelei collection that adds three things DiceBear alone does not give you: coherent demographic profiles, a small genetics engine, and a fluent builder that feels good to use from a game loop.

What it does

The smallest useful snippet:

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // weighted ethnicity → coherent skin/haircut/beard
  .setMood(Mood.Happy)
  .buildSvg();

That single chain picks a weighted ethnicity from Japanese demographics, draws a skin tone and hair color that go together, picks a haircut from the right gender subgroup, then locks eyes/eyebrows/mouth into "happy" mode. The result comes out as SVG or, with sharp installed, as PNG at any size.

A character is just a CharacterConfig object -- face, hair, accessories, presentation. The builder mutates it internally, and you can export it as JSON, base64, or file, then reload it identically. For Kurekuta that matters: a card stores the config, not the rendered image. So the art is always reproducible and a card stays tiny.

Coherent demographic profiles, not random pixels

DiceBear options are uniform selectors. Pass ["#ffdbb4", "#2c1b18"] for skin color and you get one or the other with equal probability -- fine for a logo, useless for "give me someone from Brazil."

character-factory ships a country → ethnicity → traits pipeline:

// What's in the module:
ethnicitiesByCountry[Country.Brazil] = [
  { ethnicity: Ethnicity.WestEuropean,  weight: 35 },
  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },
  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...
];

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {
  skinColors: [
    { color: SkinColor.Light,  weight: 35 },
    { color: SkinColor.Warm,   weight: 40 },
    { color: SkinColor.Medium, weight: 20 },
    // ...
  ],
  hairColors: [/* mostly black/dark brown, no blond */],
  hairCuts:   { male: [...], female: [...] },
  beardProbability: 0.15,
};

Each layer is a weighted draw. The weights are not a sociology thesis -- they're a heuristic that stops "from Japan" from producing a redhead and "from Sweden" from producing jet black. The whole pipeline boils down to one call: setCountry(country) or randomizeFromCountry(country, gender?).

A small genetics engine

The function I had the most fun with: projectChild. Two factories can produce a child whose traits are inherited with approximate biological dominance:

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

Under the hood, it's a deliberately tiny model. Each parent carries a 2-allele genotype, one drawn from each side, combined into dominant or recessive:

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

Traits with a real dominance axis (skin, eyes, hair) resolve through an explicit ordered list -- dark dominates light, brown/black eyes dominate blue, jet black dominates blond:

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // most recessive
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // most dominant
] as const;

resolveByRank finds each parent's index, takes the highest on a "dominant" allele combination and the lowest on "recessive". Fantasy colors (pastel pink, lilac) are not in the order -- they do a 50/50 coin flip, which is the right behavior: they're not biological, so dominance makes no sense.

Freckles model MC1R: 75% if both parents have them, 25% if one carries them, 0% if neither. Beards are SRY-linked: dropped if the child is female, otherwise inherited from whichever parent had one. Haircuts are not biological at all -- it's a cultural choice, so the child picks from its own gender pool, preserving texture when possible.

None of this is publication-grade genetics. It's a feel layer: kids look like a plausible mix of their parents, not the average of two strangers.

The less glamorous engineering parts that mattered

A few low-visibility details that still earned their place in the diff:

A safer pick. The original returned undefined cast as T on an empty array. With strict + noUncheckedIndexedAccess in TypeScript, that's a lie the compiler signs off on. The new version throws a RangeError -- caught immediately at the call site instead of producing undefined props three levels down.

A deepMerge that does not corrupt arrays. The old recursion kicked in whenever the source value was an object, even when the target was null or an array. merge({tags: ["a"]}, {tags: ["b"]}) produced {tags: {0: "b"}}. The new version only recurses when both sides are plain objects.

Parallel batch rendering. batchFactory rendered PNGs in a serialized loop -- a 1000-card export took forever. It's now a worker pool with configurable concurrency (4 by default), preserving result order by writing into a pre-sized array:

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

On a 1000-character export, that turned a coffee break into a "wait, it's done already?"

A sharp error message that actually says something. buildPng lazily imports sharp because it's an optional dependency you don't want to force on SVG-only users. The old catch swallowed the real error and always said "sharp is required." If the actual failure was a version conflict or a broken native binding, you spent ten minutes reinstalling an already-installed package. The new version still tells you to install it, but includes the underlying error.

What's next

The module is at 1.1.1 on the character-factory repo. The genetics engine is the ideal place to keep iterating -- there's no test suite yet, so coherence invariants ("a Brazilian character of East-Asian descent will never get jet-black eyes with platinum hair") are only enforced by the weights. Adding bun test or vitest and writing a coherence test that runs ten thousand randomizeFromCountry per country is the next step.

Kurekuta itself is private for now, but every card you'll ever see in it is just a CharacterConfig blob and a buildPng() away from existing.

Construire character-factory : des avatars avec un système génétique

J'avais besoin de milliers d'avatars crédibles et distincts pour Kurekuta -- un projet de jeu de cartes privé où chaque carte contient un "ADN" de personnage que le moteur de rendu transforme en portrait. Acheter un pack tout fait, ça se serait vu. Générer des avatars DiceBear au seed par personnage, ça donnait du n'importe quoi : une carte à l'univers japonais pouvait tomber sur une blonde scandinave, et deux "frères et sœurs" ressemblaient à des inconnus.

J'ai donc écrit character-factory -- un module TypeScript par-dessus la collection Lorelei de DiceBear qui apporte trois fonctionnalités que DiceBear seul ne donne pas : des profils démographiques cohérents, un petit moteur de génétique, et un builder fluide agréable à utiliser depuis une boucle de jeu.

Ce que ça fait

Le plus petit snippet utile :

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // ethnicité pondérée → peau/cheveux/coupe/barbe cohérents
  .setMood(Mood.Happy)
  .buildSvg();

Cette simple chaîne pioche une ethnie pondérée par la démographie japonaise, tire un teint et une couleur de cheveux qui vont ensemble, choisit une coupe dans le bon sous-groupe de genre, puis verrouille les yeux/sourcils/bouche en mode "joyeux". Le résultat sort en SVG ou, avec sharp installé, en PNG à n'importe quelle taille.

Un personnage n'est qu'un objet CharacterConfig -- visage, cheveux, accessoires, présentation. Le builder le modifie en interne, et tu peux l'exporter en JSON, base64 ou fichier, puis le recharger à l'identique. Pour Kurekuta c'est crucial : une carte stocke la config, pas l'image rendue. Du coup l'art est toujours reproductible et la taille d'une carte reste minuscule.

Des profils démographiques cohérents, pas du pixel aléatoire

Les options DiceBear sont des sélecteurs uniformes. Passe ["#ffdbb4", "#2c1b18"] pour la couleur de peau et t'auras l'un ou l'autre avec la même probabilité -- OK pour un logo, inutile pour "donne-moi un personnage du Brésil."

character-factory embarque un pipeline pays → ethnicité → traits :

// Ce qu'il y a dans le module :
ethnicitiesByCountry[Country.Brazil] = [
  { ethnicity: Ethnicity.WestEuropean,  weight: 35 },
  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },
  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...
];

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {
  skinColors: [
    { color: SkinColor.Light,  weight: 35 },
    { color: SkinColor.Warm,   weight: 40 },
    { color: SkinColor.Medium, weight: 20 },
    // ...
  ],
  hairColors: [/* surtout noir/brun foncé, pas de blond */],
  hairCuts:   { male: [...], female: [...] },
  beardProbability: 0.15,
};

Chaque couche est un tirage pondéré. Les poids ne sont pas une thèse de socio -- c'est une heuristique qui empêche "venu du Japon" de produire un roux et "venu de Suède" de produire un noir de jais. Tout le pipeline se résume à un seul appel : setCountry(country) ou randomizeFromCountry(country, gender?).

Un petit moteur de génétique

La fonction sur laquelle je me suis le plus amusé : projectChild. Deux factories peuvent produire un enfant dont les traits sont hérités avec une dominance biologique approximative :

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

Sous le capot, c'est un modèle volontairement minuscule. Chaque parent porte un génotype à 2 allèles, un tiré de chaque côté, combiné en dominant ou récessif :

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

Les traits qui ont un vrai axe de dominance (peau, yeux, cheveux) sont résolus par une liste ordonnée explicite -- le foncé domine le clair, les yeux marron/noir dominent le bleu, le noir de jais domine le blond :

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // le plus récessif
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // le plus dominant
] as const;

resolveByRank trouve l'index de chaque parent, prend le plus élevé sur une combinaison d'allèles "dominante" et le plus bas sur "récessive". Les couleurs fantasy (rose pastel, lilas) ne sont pas dans l'ordre -- elles font un pile ou face 50/50, ce qui est le bon comportement : elles ne sont pas biologiques, donc la dominance n'a pas de sens.

Les taches de rousseur modélisent MC1R : 75 % si les deux parents en ont, 25 % si un seul en porte, 0 % si aucun. La barbe est liée au SRY : retirée si l'enfant est une femme, sinon héritée du parent qui en avait une. La coupe de cheveux n'a rien de biologique -- c'est un choix culturel, donc l'enfant pioche dans son propre pool de genre, en préservant la texture si possible.

Rien de tout ça n'est de la génétique digne d'une publication. C'est une couche de ressenti : les gamins ressemblent à un mélange plausible de leurs parents, pas à la moyenne de deux inconnus.

Les parties ingénierie moins glamour qui ont compté

Quelques détails peu visibles mais qui ont mérité leur place dans le diff :

Un pick plus sûr. L'original renvoyait undefined casté en T sur un tableau vide. Avec strict + noUncheckedIndexedAccess en TypeScript, c'est un mensonge que le compilateur signe. La nouvelle version lance une RangeError -- attrapée immédiatement au site d'appel au lieu de produire des props undefined trois niveaux plus bas.

Un deepMerge qui ne corrompt pas les tableaux. L'ancienne récursion s'activait dès que la valeur source était un objet, même si la cible était null ou un tableau. merge({tags: ["a"]}, {tags: ["b"]}) produisait {tags: {0: "b"}}. La nouvelle version ne récure que quand les deux côtés sont des objets simples.

Rendu batch en parallèle. batchFactory rendait les PNG en boucle sérialisée -- une exportation de 1000 cartes prenait des plombes. C'est maintenant un pool de workers avec une concurrence configurable (4 par défaut), qui préserve l'ordre des résultats en écrivant dans un tableau pré-dimensionné :

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

Sur une exportation de 1000 personnages, ça a transformé une pause-café en un "c'est déjà fini ?"

Un message d'erreur sharp qui dit quelque chose. buildPng importe sharp en paresseux parce que c'est une dépendance optionnelle que tu ne veux pas imposer aux utilisateurs SVG-only. L'ancien catch avalait la vraie erreur et disait toujours "sharp is required." Si l'échec réel était un conflit de version ou un problème de bindings natifs, tu passais dix minutes à réinstaller un paquet déjà installé. La nouvelle version te dit toujours de l'installer, mais inclut l'erreur sous-jacente.

La suite

Le module est en 1.1.1 sur le dépôt character-factory. Le moteur génétique est l'endroit idéal pour continuer d'itérer -- il n'y a pas encore de suite de tests, donc les invariants de cohérence ("un personnage brésilien d'ascendance est-asiatique n'aura jamais les yeux noirs de jais avec des cheveux platine") ne sont assurés que par les poids. Ajouter bun test ou vitest et écrire un test de cohérence qui lance dix mille randomizeFromCountry par pays, c'est la prochaine étape.

Kurekuta lui-même est privé pour l'instant, mais chaque carte que tu verras un jour dedans n'est qu'un blob CharacterConfig et un buildPng() d'exister.

搭建 character-factory：带遗传系统的头像

Kurekuta 需要成千上万张可信又各不相同的人物头像，这是个私有卡牌游戏项目，每张卡存一段人物"DNA"，渲染引擎把它变成肖像。买现成素材包，一眼假。按人物 seed 随机 DiceBear，结果是灾难：日本世界观的卡能抽出金发北欧人，亲"兄妹"长得像陌生人。

于是我写了 character-factory，一个盖在 DiceBear Lorelei 集合上的 TypeScript 模块，补了 DiceBear 本身给不了的三样东西：人口统计学一致的画像、小遗传引擎、好用的链式 builder，在游戏循环里调用很舒服。

它能干嘛

最短的有用 snippet：

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // 按族群加权 → 肤色/发色/发型/胡子自洽
  .setMood(Mood.Happy)
  .buildSvg();

这一串做了：按日本人口加权抽族群，抽配套的肤色和发色，按性别分组选发型，锁眼/眉/嘴到"开心"态。结果出 SVG，装了 sharp 还能出任意尺寸 PNG。

人物就是一个 CharacterConfig 对象，脸、头发、饰品、表情。builder 在内部改它，你可以导出 JSON、base64、文件，再原样读回。对 Kurekuta 很关键：卡只存配置，不存渲染图。美术永远可复现，卡面积极小。

人口统计学一致，而不是纯随机像素

DiceBear 的选项是均匀选择器。传 ["#ffdbb4", "#2c1b18"] 当肤色，两个颜色等概率出，做 logo 行，做"给我来个巴西人"不行。

character-factory 内置国家 → 族群 → 特征的流水线：

// 模块里是这样的：
ethnicitiesByCountry[Country.Brazil] = [
  { ethnicity: Ethnicity.WestEuropean,  weight: 35 },
  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },
  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...
];

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {
  skinColors: [
    { color: SkinColor.Light,  weight: 35 },
    { color: SkinColor.Warm,   weight: 40 },
    { color: SkinColor.Medium, weight: 20 },
    // ...
  ],
  hairColors: [/* 基本黑和深棕，没金发 */],
  hairCuts:   { male: [...], female: [...] },

};

每一层都是加权抽。权重不是社会学论文，是启发式："来自日本"不出红发，"来自瑞典"不出深黑。整条流水线收敛成一个调用：setCountry(country) 或 randomizeFromCountry(country, gender?)。

小遗传引擎

我玩得最开心的函数：projectChild。两个 factory 能生孩子，孩子的特征按近似显隐性遗传：

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

底层是故意做小的模型。每个亲本带 2 等位基因的基因型，两边各抽一个，按显隐性合并：

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

有明确显隐轴的特征（肤、眼、发）走显式排序表，深色压浅色，棕黑眼压蓝眼，深黑发压金发：

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // 最隐性
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // 最显性
] as const;

resolveByRank 看双亲的 index，"显性"组合取高的，"隐性"取低的。幻想色（粉、紫）不在表里，50/50 抛硬币，这处理是对的：它们不生物，显隐无意义。

雀斑按 MC1R 建模：双亲都有 75%，一方有 25%，都没有 0%。胡子跟 SRY 走：孩子是女孩直接去掉，否则继承有胡子那方。发型不生物，是文化选择，孩子从自己性别池里抽，尽量保留质感。

这都不是能发论文的遗传学。是手感层：孩子像双亲 plausibly 的混合，不像两个陌生人的平均。

不起眼但重要的工程活

几个藏在 diff 里但值得说的细节：

更安全的 pick。 原版空数组返回 undefined 强转 T，开了 strict + noUncheckedIndexedAccess 的 TypeScript 里，这是编译器签字的谎言。新版抛 RangeError，在调用处立刻炸，而不是三层之后冒出 undefined 的 props。

不腐蚀数组的 deepMerge。 老递归只要源值是对象就 recurse，哪怕目标是 null 或数组。merge({tags: ["a"]}, {tags: ["b"]}) 得到 {tags: {0: "b"}}。新版只在两边都是 plain object 时才 recurse。

并行批量渲染。 batchFactory 原来是串行渲 PNG，导出 1000 张卡要等到天荒地老。现在是 worker 池，可配并发（默认 4），写预分配数组保序：

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

1000 个人物导出，从"去泡咖啡"变成"啊？渲完了？"

会说话的 sharp 报错。 buildPng 懒加载 sharp，因为是不想强加给纯 SVG 用户的可选依赖。老 catch 吞掉真错误，永远说"sharp is required."。真问题是版本冲突或 native binding 坏掉时，你白重装十分钟。新版照样提示安装，但把底层错误一起带上。

下一步

模块在 character-factory 仓库 的 1.1.1。遗传引擎是最值得继续迭代的地方，现在还没测试套件，一致性约束（"东亚血统的巴西人物不会黑眼睛配铂金发"）只靠权重保证。下一步是加上 bun test 或 vitest，写个一致性测试，每个国家跑一万次 randomizeFromCountry。

Kurekuta 本体暂时私有，但以后你看到的每张卡，都只是一个 CharacterConfig blob 加一次 buildPng()。

character-factoryを作る：遺伝子付きアバターシステム

Kurekuta用に、信憑性があって互いに違うアバターが何千も要った。プライベートのカードゲームプロジェクトで、各カードはキャラクターの「DNA」を持ってて、レンダーエンジンが肖像に変換する。既製パックを買えばバレる。キャラごとにDiceBearをシード生成すればめちゃくちゃになる。日本が舞台のカードがスカンジナビアの金髪になったり、「兄弟」が他人みたいになったりする。

だからcharacter-factoryを書いた。DiceBearのLoreleiコレクションの上のTypeScriptモジュールで、DiceBear単体にない3機能を足す。一貫した人口統計プロフィールと小さな遺伝エンジンと、ゲームループから使いやすい流暢ビルダーだ。

できること

最小の useful スニペットはこうだ。

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // 民族重み付けから肌や髪や髭が一貫する
  .setMood(Mood.Happy)
  .buildSvg();

この単純な連鎖が、日本の人口統計で重み付けした民族を引いて、合う肌色と髪色を引いて、性別サブグループから合う髪型を選んで、目や眉や口を「嬉しい」モードに固定する。結果はSVGで出る。sharpが入ってれば任意サイズのPNGでも出る。

キャラクターはCharacterConfigオブジェクト1つに過ぎない。顔、髪、アクセサリ、見せ方だ。ビルダーが内部で変更して、JSONやbase64やファイルで出して、そのまま読み戻せる。Kurekutaでは大事だ。カードはレンダー画像じゃなく設定を保存する。だからアートは常に再現可能で、カード1枚のサイズは極小のまま保てる。

ランダムピクセルじゃない一貫した人口統計プロフィール

DiceBearの選択肢は一様セレクタだ。肌色に["#ffdbb4", "#2c1b18"]を渡せば同確率でどっちかが出る。ロゴにはいいけど「ブラジルの人出して」には役立たない。

character-factoryは国から民族から特徴へのパイプラインを内蔵してる。

// モジュール内ではこうなってる：
ethnicitiesByCountry[Country.Brazil] = [
  { ethnicity: Ethnicity.WestEuropean,  weight: 35 },
  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },
  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...
];

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {

    { color: SkinColor.Light,  weight: 35 },

  ],

  hairCuts:   { male: [...], female: [...] },
  beardProbability: 0.15,

各層が重み付き抽選だ。重みは社会学の論文じゃない。「日本出身」が赤毛になったり「スウェーデン出身」が真っ黒になったりを防ぐヒューリスティックだ。パイプライン全体は1呼び出しにまとまる。setCountry(country)かrandomizeFromCountry(country, gender?)だ。

小さな遺伝エンジン

いちばん楽しんだ機能がprojectChildだ。2つのファクトリーが、だいたいの優劣生物学で継承される特徴の子を産める。

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

中身はわざとちっぽけなモデルだ。各親は2対立遺伝子の遺伝子型を持って、両側から1つずつ引いて、優性か劣性に組み合わせる。

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

優劣の本当の軸がある特徴（肌、目、髪）は明示の順序リストで解く。濃いが薄いに勝ち、茶や黒目が青目に勝ち、漆黒が金髪に勝つ。

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // いちばん劣性
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // いちばん優性
] as const;

resolveByRankは両親の順位を見て、「優性」組み合わせでは高い方、「劣性」組み合わせでは低い方を取る。ファンタジー色（パステルピンク、ライラック）は順序外だ。50/50のコイントスになる。正しい挙動だ。生物学的じゃないから優劣に意味はない。

そばかすはMC1Rをモデル化する。両親ともあれば75パーセント、片方だけなら25パーセント、なければ0パーセントだ。髭はSRY連動だ。子が女性なら除去、そうじゃなければ髭持ち親から継承する。髪型に生物学はない。文化の選択だから、子は自分の性別プールから引く。質感は保てれば保つ。

どれも論文になる遺伝学じゃない。感触の層だ。子は2人の他人平均じゃなく、両親のもっともらしい混ざりに見える。

地味だけど効いた工学的部分

目立たないけどdiffに入れる価値があった詳細がいくつかある。

安全なpick。 オリジナルは空配列にTにキャストしたundefinedを返してた。TypeScriptのstrictとnoUncheckedIndexedAccessでは、コンパイラが署名する嘘だ。新版はRangeErrorを投げる。3層下のundefinedプロパティになる代わりに呼び出し元で即捕まる。

配列を壊さないdeepMerge。 古い再帰はソース値がオブジェクトなら発動してた。ターゲットがnullでも配列でもだ。merge({tags: ["a"]}, {tags: ["b"]}は{tags: {0: "b"}}を作ってた。新版は両側がプレーンオブジェクトのときだけ潜る。

並列バッチレンダー。 batchFactoryはPNGを直列ループでレンダーしてた。カード1000枚の書き出しはえらく時間がかかってた。今は設定可能並行数（デフォルト4）のワーカープールで、事前確保配列への書き込みで結果順序を保つ。

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // レンダーして保存
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

1000人書き出しが、コーヒー休憩から「もう終わったの」に変わった。

何を言ってるか分かるsharpエラーメッセージ。 buildPngはsharpを遅延importする。SVG専用ユーザーに強いりたくない任意依存だからね。古いcatchは本当のエラーを飲んでいつも「sharp is required」とだけ言ってた。本当の失敗がバージョン衝突やネイティブバインディング問題なら、入ってるパッケージの再インストールに10分溶かすことになる。新版はインストールを促しつつ、元のエラーを含める。

今後

モジュールはcharacter-factoryリポジトリで1.1.1だ。遺伝エンジンは反復を続けるのに最適な場所だ。テストスイートがまだないから、一貫性不変条件（「東アジア系のブラジル人キャラが漆黒目とプラチナ髪になることはない」）は重みだけで保たれてる。bun testかvitestを足して、国ごとに1万回randomizeFromCountryを回す一貫性テストを書くのが次の段階だ。

Kurekuta自体は今はプライベートだけど、いつかそこで見る各カードはCharacterConfigのblob1つとbuildPng()1回があるだけだ。

character-factory 만들기: 유전 시스템이 있는 아바타

Kurekuta에 쓸 믿을 만하고 서로 다른 수천 개의 아바타가 필요했어요. 각 카드가 캐릭터 "DNA"를 담고 있고 렌더링 엔진이 이를 초상화로 바꾸는 비공개 카드 게임 프로젝트예요. 기성 팩을 사는 것은 티가 날 것 같았어요. 캐릭터별 시드로 DiceBear 아바타를 생성하면 엉망이 됐어요. 일본 세계관 카드에서 스칸디나비아 금발이 나오고, "남매" 둘이 낯선 사람처럼 생겼어요.

그래서 character-factory를 썼어요. DiceBear의 Lorelei 컬렉션 위에 올린 TypeScript 모듈로, DiceBear만으로는 얻을 수 없는 세 가지 기능을 더해요. 일관된 인구통계 프로필과 작은 유전 엔진, 그리고 게임 루프에서 쓰기 편한 유창한 빌더예요.

하는 일

가장 작은 유용한 스니펫이에요.

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // 가중 민족 → 일관된 피부/머리/컷/수염
  .setMood(Mood.Happy)
  .buildSvg();

이 간단한 체인은 일본 인구통계로 가중한 민족을 뽑고, 어울리는 피부색과 머리색을 뽑고, 올바른 성별 하위 그룹에서 머리 모양을 고른 뒤, 눈과 눈썹, 입을 "행복" 모드로 고정해요. 결과는 SVG로 나오고, sharp이 설치되어 있으면 원하는 크기의 PNG로도 나와요.

캐릭터는 그저 CharacterConfig 객체예요. 얼굴, 머리, 액세서리, 표현이죠. 빌더가 내부에서 수정하고, JSON이나 base64, 파일로 내보냈다가 똑같이 다시 불러올 수 있어요. Kurekuta에는 이것이 중요해요. 카드에는 렌더링된 이미지가 아니라 설정이 저장되거든요. 그래서 아트는 항상 재현 가능하고 카드 크기는 아주 작게 유지돼요.

무작위 픽셀이 아닌, 일관된 인구통계 프로필

DiceBear 옵션은 균등 선택기예요. 피부색에 ["#ffdbb4", "#2c1b18"]를 넘기면 둘 중 하나가 같은 확률로 나와요. 로고에는 괜찮지만 "브라질 사람 캐릭터를 줘" 같은 요청에는 쓸모없어요.

character-factory는 국가에서 민족으로, 민족에서 특성으로 이어지는 파이프라인을 내장하고 있어요.

// 모듈 안에 있는 내용:
ethnicitiesByCountry[Country.Brazil] = [
  { ethnicity: Ethnicity.WestEuropean,  weight: 35 },
  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },
  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...
];

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {
  skinColors: [
    { color: SkinColor.Light,  weight: 35 },
    { color: SkinColor.Warm,   weight: 40 },
    { color: SkinColor.Medium, weight: 20 },
    // ...
  ],
  hairColors: [/* 주로 검정/짙은 갈색, 금발 없음 */],
  hairCuts:   { male: [...], female: [...] },
  beardProbability: 0.15,
};

각 층은 가중 추첨이에요. 가중치가 사회학 논문은 아니고, "일본 출신"이 빨간 머리로 나오거나 "스웨덴 출신"이 새까만 머리로 나오는 것을 막는 휴리스틱이에요. 파이프라인 전체는 setCountry(country)나 randomizeFromCountry(country, gender?) 한 번 호출로 요약돼요.

작은 유전 엔진

제가 가장 재미있게 만든 기능이에요. projectChild예요. 두 팩토리가 대략적인 생물학적 우성을 따라 특성을 물려받은 아이를 만들 수 있어요.

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

내부적으로는 일부러 아주 작게 만든 모델이에요. 각 부모는 2개의 대립유전자로 된 유전자형을 지니고, 양쪽에서 하나씩 뽑아 우성이나 열성으로 조합해요.

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

진짜 우성 축이 있는 특성(피부, 눈, 머리)은 명시적인 순서 목록으로 풀어요. 짙은 색이 옅은 색을 누르고, 갈색과 검은 눈이 파란 눈을 누르고, 새까만 머리가 금발을 눌러요.

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // 가장 열성
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // 가장 우성
] as const;

resolveByRank는 각 부모의 인덱스를 찾아서, 대립유전자 조합이 "우성"이면 더 높은 쪽을, "열성"이면 더 낮은 쪽을 가져와요. 판타지 색(파스텔 분홍, 라일락)은 순서에 없어요. 50대 50 동전 던지기를 하는데, 이것이 올바른 동작이에요. 생물학적이지 않으니 우성이 의미가 없거든요.

주근깨는 MC1R을 모델링해요. 부모 둘 다 있으면 75퍼센트, 한쪽만 있으면 25퍼센트, 없으면 0퍼센트예요. 수염은 SRY와 연결돼요. 아이가 여자면 제거하고, 아니면 수염이 있던 부모에게서 물려받아요. 머리 모양은 생물학과 무관해요. 문화적 선택이라서 아이는 자신의 성별 풀에서 뽑되, 가능하면 질감을 유지해요.

이 중 어느 것도 논문에 낼 유전학은 아니에요. 느낌의 층이에요. 아이들이 낯선 둘의 평균이 아니라 부모를 그럴듯하게 섞은 모습으로 나와요.

덜 화려하지만 중요했던 엔지니어링 부분

눈에 잘 띄지 않지만 diff에 들어갈 가치가 있던 세부 사항 몇 가지예요.

더 안전한 pick. 원래 함수는 빈 배열에 undefined를 T로 캐스팅해서 돌려줬어요. TypeScript의 strict와 noUncheckedIndexedAccess에서는 컴파일러가 서명하는 거짓말이에요. 새 버전은 RangeError를 던져요. 세 단계 아래에서 undefined props를 만드는 대신 호출 지점에서 바로 잡혀요.

배열을 망가뜨리지 않는 deepMerge. 예전 재귀는 소스 값이 객체이기만 하면 대상이 null이나 배열이어도 발동했어요. merge({tags: ["a"]}, {tags: ["b"]})가 {tags: {0: "b"}}를 만들었어요. 새 버전은 양쪽이 모두 일반 객체일 때만 재귀해요.

병렬 배치 렌더링. batchFactory는 PNG를 직렬 루프로 렌더링했어요. 1000장 카드 내보내기에 한참 걸렸어요. 이제는 설정 가능한 동시성(기본값 4)의 워커 풀로, 미리 크기를 잡은 배열에 쓰면서 결과 순서를 유지해요.

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

1000개 캐릭터 내보내기에서 커피 한 잔 마실 시간이 "벌써 끝났다고?"로 바뀌었어요.

제대로 말해 주는 sharp 오류 메시지. buildPng는 SVG 전용 사용자에게 강요하고 싶지 않은 선택적 의존성이라 sharp을 느리게 import해요. 예전 catch는 진짜 오류를 삼키고 항상 "sharp is required."라고 말했어요. 실제 실패가 버전 충돌이나 네이티브 바인딩 문제면, 이미 설치된 패키지를 다시 설치하면서 10분을 날렸어요. 새 버전은 설치하라고 말하면서도 근본 오류를 함께 보여줘요.

모듈은 character-factory 저장소에서 1.1.1 버전이에요. 유전 엔진이 계속 다듬기 좋은 지점이에요. 아직 테스트 모음이 없어서, 일관성 불변식("동아시아 조상의 브라질 캐릭터는 절대 새까만 눈에 백금발이 되지 않는다")은 가중치로만 보장돼요. bun test나 vitest를 추가하고 국가별로 만 번씩 randomizeFromCountry를 돌리는 일관성 테스트를 쓰는 것이 다음 단계예요.

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // renderla ve kaydet
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);

await Promise.all(Array.from({ length: concurrency }, () => worker()));

1000 karakterlik bir dışa aktarmada bu kahve molasını "çoktan bitti mi?"ye dönüştürdü.

Yeni sürüm kurmanı yine söyler ama alttaki hatayı da içerir.

Costruire character-factory: avatar con un sistema genetico

Mi servivano migliaia di avatar credibili e distinti per Kurekuta: un progetto privato di gioco di carte dove ogni carta contiene un "DNA" di personaggio che il motore di rendering trasforma in ritratto. Generare avatar DiceBear a seed per personaggio, dava roba a caso: una carta a universo giapponese poteva cadere su una bionda scandinava, e due "fratelli e sorelle" sembravano sconosciuti.

Quindi ho scritto character-factory: un modulo TypeScript sopra la collezione Lorelei di DiceBear che porta tre funzionalità che DiceBear da solo non dà: profili demografici coerenti, un piccolo motore di genetica, e un builder fluido piacevole da usare da un ciclo di gioco.

Cosa fa

Lo snippet utile più piccolo:

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // etnia pesata → pelle/capelli/taglio/barba coerenti
  .setMood(Mood.Happy)
  .buildSvg();

Questa semplice catena pesca un'etnia pesata dalla demografia giapponese, tira una tinta e un colore di capelli che stanno bene insieme, sceglie un taglio nel giusto sottogruppo di genere, poi blocca occhi/sopracciglia/bocca in modalità "felice". Il risultato esce in SVG o, con sharp installato, in PNG a qualsiasi taglia.

Un personaggio è solo un oggetto CharacterConfig: viso, capelli, accessori, presentazione. Il builder lo modifica internamente, e puoi esportarlo in JSON, base64 o file, poi ricaricarlo identico. Per Kurekuta è cruciale: una carta salva la config, non l'immagine renderizzata. Così l'arte è sempre riproducibile e la taglia di una carta resta minuscola.

Profili demografici coerenti, non pixel a caso

Le opzioni DiceBear sono selettori uniformi. Passi ["#ffdbb4", "#2c1b18"] per il colore di pelle e avrai l'uno o l'altro con la stessa probabilità: ok per un logo, inutile per "dammi un personaggio del Brasile."

character-factory imbarca una pipeline paese, poi etnia, poi tratti:

// Cosa c'è nel modulo:
ethnicitiesByCountry[Country.Brazil] = [

  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },

Ogni strato è un'estrazione pesata. I pesi non sono una tesi di socio: è un'euristica che impedisce a "venuto dal Giappone" di produrre un rosso e a "venuto dalla Svezia" di produrre un nero corvino. Tutta la pipeline si riassume in una sola chiamata: setCountry(country) o randomizeFromCountry(country, gender?).

Un piccolo motore di genetica

La funzione su cui mi sono divertito di più: projectChild. Due factory possono produrre un figlio i cui tratti sono ereditati con una dominanza biologica approssimativa:

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

Sotto il cofano, è un modello volutamente minuscolo. Ogni genitore porta un genotipo a 2 alleli, uno tirato da ogni lato, combinato in dominante o recessivo:

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

I tratti che hanno un vero asse di dominanza (pelle, occhi, capelli) sono risolti da una lista ordinata esplicita: lo scuro domina il chiaro, gli occhi marroni/neri dominano il blu, il nero corvino domina il biondo:

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // il più recessivo
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // il più dominante
] as const;

resolveByRank trova l'indice di ogni genitore, prende il più alto su una combinazione di alleli "dominante" e il più basso su "recessiva". I colori fantasy (rosa pastello, lilla) non sono nell'ordine: fanno un testa o croce 50/50, che è il comportamento giusto: non sono biologici, quindi la dominanza non ha senso.

Le lentiggini modellano MC1R: 75% se entrambi i genitori ne hanno, 25% se ne porta solo uno, 0% se nessuno. La barba è legata a SRY: rimossa se il figlio è femmina, altrimenti ereditata dal genitore che ne aveva una. Il taglio di capelli non ha niente di biologico: è una scelta culturale, quindi il figlio pesca nel suo pool di genere, preservando la texture se possibile.

Niente di tutto questo è genetica da pubblicazione. È uno strato di sensazione: i ragazzini assomigliano a un mix plausibile dei loro genitori, non alla media di due sconosciuti.

Le parti ingegneria meno glamour che hanno contato

Qualche dettaglio poco visibile ma che ha meritato il suo posto nel diff:

Un pick più sicuro. L'originale restituiva undefined castato a T su una tabella vuota. Con strict + noUncheckedIndexedAccess in TypeScript, è una bugia che il compilatore firma. La nuova versione lancia una RangeError: beccata subito al sito di chiamata invece di produrre prop undefined tre livelli più in basso.

Un deepMerge che non corrompe le tabelle. La vecchia ricorsione scattava appena il valore sorgente era un oggetto, anche se il target era null o una tabella. merge({tags: ["a"]}, {tags: ["b"]}) produceva {tags: {0: "b"}}. La nuova versione ricorre solo quando entrambi i lati sono oggetti semplici.

const worker = async () => {

    if (i >= count) return;
    // renderizza e salva
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };

Su un'esportazione di 1000 personaggi, ha trasformato una pausa caffè in un "già finito?"

Un messaggio di errore sharp che dice qualcosa. buildPng importa sharp in pigro perché è una dipendenza opzionale che non vuoi imporre agli utenti solo SVG. Il vecchio catch ingoiava il vero errore e diceva sempre "sharp is required." Se il vero fallimento era un conflitto di versione o un problema di binding nativi, passavi dieci minuti a reinstallare un pacchetto già installato. La nuova versione ti dice sempre di installarlo, ma include l'errore sottostante.

Il seguito

Il modulo è in 1.1.1 sul repository character-factory. Il motore genetico è il posto ideale per continuare a iterare: non c'è ancora una suite di test, quindi gli invarianti di coerenza ("un personaggio brasiliano di ascendenza est-asiatica non avrà mai gli occhi neri corvini coi capelli platino") sono assicurati solo dai pesi. Aggiungere bun test o vitest e scrivere un test di coerenza che lancia diecimila randomizeFromCountry per paese, è il prossimo passo.

character-factory bauen: Avatare mit Genetiksystem

Ich brauchte Tausende glaubwürdige und unterschiedliche Avatare für Kurekuta, ein privates Kartenspielprojekt, bei dem jede Karte eine Charakter-"DNA" enthält, die die Render-Engine in ein Porträt verwandelt. Ein fertiges Pack zu kaufen hätte man gesehen. DiceBear-Avatare pro Charakter zu seeden gab Unsinn: Eine Karte mit japanischem Universum konnte auf eine skandinavische Blondine fallen, und zwei "Geschwister" sahen aus wie Fremde.

Also habe ich character-factory geschrieben, ein TypeScript-Modul auf der Lorelei-Collection von DiceBear, das drei Funktionen mitbringt, die DiceBear allein nicht gibt: konsistente demografische Profile, eine kleine Genetik-Engine und einen flüssigen Builder, der sich angenehm aus einer Spielschleife nutzen lässt.

Was es tut

Das kleinste nützliche Snippet:

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // gewichtete Ethnizität → konsistente Haut/Haare/Schnitt/Bart
  .setMood(Mood.Happy)
  .buildSvg();

Diese einfache Kette zieht eine nach der japanischen Demografie gewichtete Ethnie, zieht einen Teint und eine Haarfarbe, die zusammenpassen, wählt einen Schnitt aus der passenden Gender-Untergruppe und verriegelt dann Augen/Brauen/Mund in den "fröhlich"-Modus. Das Ergebnis kommt als SVG raus oder, mit installiertem sharp, als PNG in beliebiger Größe.

Ein Charakter ist nur ein CharacterConfig-Objekt, Gesicht, Haare, Accessoires, Darstellung. Der Builder verändert es intern, und du kannst es als JSON, Base64 oder Datei exportieren und dann identisch wieder laden. Für Kurekuta ist das entscheidend: Eine Karte speichert die Config, nicht das gerenderte Bild. Dadurch ist die Kunst immer reproduzierbar und die Größe einer Karte bleibt winzig.

Konsistente demografische Profile statt zufälliger Pixel

Die DiceBear-Optionen sind uniforme Selektoren. Gib ["#ffdbb4", "#2c1b18"] für die Hautfarbe an und du bekommst das eine oder das andere mit derselben Wahrscheinlichkeit, OK für ein Logo, nutzlos für "gib mir einen Charakter aus Brasilien."

character-factory bringt eine Land → Ethnie → Merkmale-Pipeline mit:

// Was im Modul steckt :
ethnicitiesByCountry[Country.Brazil] = [
  { ethnicity: Ethnicity.WestEuropean,  weight: 35 },
  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },
  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...
];

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {
  skinColors: [
    { color: SkinColor.Light,  weight: 35 },
    { color: SkinColor.Warm,   weight: 40 },
    { color: SkinColor.Medium, weight: 20 },
    // ...
  ],
  hairColors: [/* vor allem schwarz/dunkelbraun, kein blond */],
  hairCuts:   { male: [...], female: [...] },
  beardProbability: 0.15,

Jede Schicht ist eine gewichtete Ziehung. Die Gewichte sind keine Sozio-These, es ist eine Heuristik, die verhindert, dass "aus Japan" einen Rothaarigen produziert und "aus Schweden" ein tiefes Schwarz. Die ganze Pipeline löst sich in einen einzigen Aufruf auf: setCountry(country) oder randomizeFromCountry(country, gender?).

Eine kleine Genetik-Engine

Die Funktion, mit der ich mich am meisten amüsiert habe: projectChild. Zwei Factories können ein Kind produzieren, dessen Merkmale mit ungefährer biologischer Dominanz vererbt werden:

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

Unter der Haube ist es ein absichtlich winziges Modell. Jeder Elternteil trägt einen Genotyp mit 2 Allelen, eines von jeder Seite gezogen, kombiniert zu dominant oder rezessiv:

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

Merkmale, die eine echte Dominanzachse haben (Haut, Augen, Haare), werden über eine explizite geordnete Liste aufgelöst, dunkel dominiert hell, braune/schwarze Augen dominieren blau, tiefes Schwarz dominiert blond:

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // am rezessivsten
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // am dominantesten
] as const;

resolveByRank findet den Index jedes Elternteils, nimmt den höheren bei einer "dominanten" Allelkombination und den niedrigeren bei "rezessiv". Fantasy-Farben (Pastellrosa, Flieder) stehen nicht in der Ordnung, sie machen 50/50-Kopf-oder-Zahl, was das richtige Verhalten ist: Sie sind nicht biologisch, also ergibt Dominanz keinen Sinn.

Sommersprossen modellieren MC1R: 75 %, wenn beide Eltern sie haben, 25 %, wenn nur einer sie trägt, 0 %, wenn keiner. Der Bart hängt an SRY: entfernt, wenn das Kind eine Frau ist, sonst vom Elternteil vererbt, der einen hatte. Der Haarschnitt hat nichts Biologisches, es ist eine kulturelle Wahl, also zieht das Kind aus seinem eigenen Gender-Pool und bewahrt dabei wenn möglich die Textur.

Nichts davon ist publikationswürdige Genetik. Es ist eine Gefühlsschicht: Die Kinder sehen aus wie eine plausible Mischung ihrer Eltern, nicht wie der Durchschnitt zweier Fremder.

Die weniger glamourösen Engineering-Teile, die gezählt haben

Einige wenig sichtbare Details, die ihren Platz im Diff verdient haben:

Ein sichereres pick. Das Original gab undefined gecastet zu T bei leerem Array zurück. Mit strict + noUncheckedIndexedAccess in TypeScript ist das eine Lüge, die der Compiler unterschreibt. Die neue Version wirft einen RangeError, sofort an der Aufrufstelle gefangen, statt drei Ebenen tiefer undefined-Props zu produzieren.

Ein deepMerge, das Arrays nicht korrumpiert. Die alte Rekursion aktivierte sich, sobald der Quellwert ein Objekt war, selbst wenn das Ziel null oder ein Array war. merge({tags: ["a"]}, {tags: ["b"]}) produzierte {tags: {0: "b"}}. Die neue Version rekursiert nur, wenn beide Seiten einfache Objekte sind.

Paralleles Batch-Rendering. batchFactory renderte die PNGs in serialisierter Schleife, ein Export von 1000 Karten dauerte ewig. Jetzt ist es ein Worker-Pool mit konfigurierbarer Konkurrenz (Standard 4), der die Ergebnisreihenfolge bewahrt, indem er in ein vordimensioniertes Array schreibt:

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // rendern und speichern
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };

  }

await Promise.all(Array.from({ length: concurrency }, () => worker()));

Bei einem Export von 1000 Charakteren hat das eine Kaffeepause in ein "schon fertig ?" verwandelt.

Eine sharp-Fehlermeldung, die etwas aussagt. buildPng importiert sharp faul, weil es eine optionale Abhängigkeit ist, die du SVG-only-Nutzern nicht aufzwingen willst. Построить character-factory : аватары с генетической системой

Мне нужны были тысячи правдоподобных и разных аватаров для Kurekuta -- приватного проекта карточной игры, где каждая карта содержит "ДНК" персонажа, которую движок рендера превращает в портрет. Купить готовый пак было бы видно. Генерировать аватары DiceBear с сидом на персонажа давало ерунду : карта с японской вселенной могла получить скандинавскую блондинку, а двое "брата с сестрой" выглядели незнакомцами.

Поэтому я написал character-factory -- модуль TypeScript поверх коллекции Lorelei от DiceBear, который даёт три возможности, которых нет у одного DiceBear : согласованные демографические профили, маленький движок генетики и удобный текучий builder для использования из игрового цикла.

Что это делает

Самый маленький полезный сниппет :

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // взвешенный этнос → согласованные кожа/волосы/стрижка/борода
  .setMood(Mood.Happy)
  .buildSvg();

Эта простая цепочка тянет этнос, взвешенный по демографии Японии, подбирает сочетающиеся тон кожи и цвет волос, выбирает стрижку из нужной гендерной подгруппы, затем фиксирует глаза/брови/рот в "радостном" режиме. Результат выходит в SVG или, с установленным sharp, в PNG любого размера.

Персонаж это просто объект CharacterConfig -- лицо, волосы, аксессуары, подача. Builder меняет его внутри, а ты можешь экспортировать в JSON, base64 или файл, а потом загрузить обратно один в один. Для Kurekuta это критично : карта хранит конфиг, а не отрендеренную картинку. Так арт всегда воспроизводим, а размер карты остаётся крошечным.

Согласованные демографические профили, а не случайный пиксель

Опции DiceBear это равномерные селекторы. Передай ["#ffdbb4", "#2c1b18"] для цвета кожи, и получишь то или другое с равной вероятностью -- ок для логотипа, бесполезно для "дай мне персонажа из Бразилии".

character-factory везёт пайплайн страна → этнос → черты :

// Что лежит в модуле :
ethnicitiesByCountry[Country.Brazil] = [
  { ethnicity: Ethnicity.WestEuropean,  weight: 35 },
  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },
  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...
];

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {
  skinColors: [
    { color: SkinColor.Light,  weight: 35 },
    { color: SkinColor.Warm,   weight: 40 },
    { color: SkinColor.Medium, weight: 20 },
    // ...
  ],
  hairColors: [/* в основном чёрный/тёмно-русый, никакого блонда */],
  hairCuts:   { male: [...], female: [...] },
  beardProbability: 0.15,
};

Каждый слой это взвешенный розыгрыш. Веса не социологическая диссертация -- это эвристика, которая не даёт "приехавшему из Японии" получить рыжий, а "приехавшему из Швеции" получить смоляной чёрный. Весь пайплайн сводится к одному вызову : setCountry(country) или randomizeFromCountry(country, gender?).

Маленький движок генетики

Функция, с которой я развлекся сильнее всего : projectChild. Две фабрики могут произвести ребёнка, чьи черты наследуются с приблизительной биологической доминантностью :

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

Под капотом это намеренно крошечная модель. Каждый родитель несёт генотип из 2 аллелей, по одному с каждой стороны, скомбинированных в доминантный или рецессивный :

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

Черты с настоящей осью доминантности (кожа, глаза, волосы) разрешаются явным упорядоченным списком -- тёмное доминирует над светлым, карие/чёрные глаза доминируют над голубыми, смоляной чёрный доминирует над блондом :

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // самый рецессивный
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // самый доминантный
] as const;

resolveByRank находит индекс каждого родителя, берёт больший при "доминантной" комбинации аллелей и меньший при "рецессивной". Фэнтезийных цветов (пастельный розовый, сирень) в порядке нет -- они идут на монетку 50/50, и это правильное поведение : они не биологические, так что доминантность бессмысленна.

Веснушки моделируют MC1R : 75 %, если они у обоих родителей, 25 %, если носитель один, 0 %, если ни у кого. Борода связана с SRY : убирается, если ребёнок девочка, иначе наследуется от родителя, у которого была. Стрижка вообще не биология -- это культурный выбор, так что ребёнок тянет из собственного гендерного пула, по возможности сохраняя текстуру.

Ничего из этого не генетика уровня публикации. Это слой ощущений : дети выглядят как правдоподобная смесь родителей, а не как среднее двух незнакомцев.

Менее гламурные инженерные части, которые сыграли

Несколько малозаметных деталей, заслуживших место в диффе :

Более безопасный pick. Оригинал возвращал undefined, приведённый к T, на пустом массиве. Со strict + noUncheckedIndexedAccess в TypeScript это ложь с подписью компилятора. Новая версия бросает RangeError -- ловится сразу в месте вызова вместо undefined-пропсов тремя уровнями ниже.

deepMerge, не портящий массивы. Старая рекурсия включалась, как только исходное значение было объектом, даже если цель была null или массивом. merge({tags: ["a"]}, {tags: ["b"]}) давал {tags: {0: "b"}}. Новая версия рекурсирует, только когда обе стороны простые объекты.

Параллельный батч-рендер. batchFactory рендерил PNG в сериализованном цикле -- экспорт 1000 карт занимал вечность. Теперь это пул воркеров с настраиваемым параллелизмом (4 по умолчанию), сохраняющий порядок результатов записью в заранее размеренный массив :

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // рендер и сохранение
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

На экспорте 1000 персонажей это превратило перерыв на кофе в "уже всё?".

Сообщение об ошибке sharp, которое что-то говорит. buildPng импортирует sharp лениво, потому что это опциональная зависимость, которую не хочется навязывать SVG-only пользователям. Старый catch глотал настоящую ошибку и всегда говорил "sharp is required." Если реальным сбоем был конфликт версий или проблема нативных биндингов, ты тратил десять минут на переустановку уже установленного пакета. Новая версия всё равно просит установить, но включает нижележащую ошибку.

Дальше

Модуль в версии 1.1.1 в репозитории character-factory. Генетический движок идеальное место продолжать итерировать -- тестового набора пока нет, так что инварианты согласованности ("бразильский персонаж с восточноазиатским происхождением никогда не получит смоляные глаза с платиновыми волосами") держатся только на весах. Добавить bun test или vitest и написать тест согласованности, гоняющий десять тысяч randomizeFromCountry на страну, это следующий шаг.

Сама Kurekuta пока приватна, но каждая карта, что ты однажды в ней увидишь, это лишь blob CharacterConfig и один buildPng() от существования.

// Lo que hay en el módulo:
ethnicitiesByCountry[Country.Brazil] = [

Un pequeño motor de genética

La función con la que más me divertí: projectChild. Dos factories pueden producir un hijo cuyos rasgos se heredan con una dominancia biológica aproximada:

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

Bajo el capó, es un modelo deliberadamente minúsculo. Cada padre lleva un genotipo de 2 alelos, uno sacado de cada lado, combinado en dominante o recesivo:

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

Los rasgos que tienen un verdadero eje de dominancia (piel, ojos, pelo) se resuelven con una lista ordenada explícita: lo oscuro domina lo claro, los ojos marrones/negros dominan el azul, el negro azabache domina el rubio:

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // el más recesivo
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // el más dominante
] as const;

resolveByRank encuentra el índice de cada padre, toma el más alto en una combinación de alelos "dominante" y el más bajo en "recesiva". Los colores fantasía (rosa pastel, lila) no están en el orden: hacen un cara o cruz 50/50, que es el comportamiento correcto: no son biológicos, así que la dominancia no tiene sentido.

Las pecas modelan MC1R: 75% si ambos padres las tienen, 25% si solo uno las lleva, 0% si ninguno. La barba está ligada al SRY: se quita si el hijo es mujer, si no se hereda del padre que la tenía. El corte de pelo no tiene nada de biológico: es una elección cultural, así que el hijo elige de su propio pool de género, conservando la textura si es posible.

Nada de esto es genética digna de publicación. Es una capa de sensación: los críos parecen una mezcla plausible de sus padres, no la media de dos desconocidos.

Las partes de ingeniería menos glamurosas que contaron

Algunos detalles poco visibles pero que merecieron su sitio en el diff:

Un pick más seguro. El original devolvía undefined casteado a T sobre un array vacío. Con strict + noUncheckedIndexedAccess en TypeScript, es una mentira que firma el compilador. La nueva versión lanza un RangeError: capturado de inmediato en el sitio de llamada en vez de producir props undefined tres niveles más abajo.

Un deepMerge que no corrompe los arrays. La vieja recursión se activaba en cuanto el valor fuente era un objeto, aunque el destino fuera null o un array. merge({tags: ["a"]}, {tags: ["b"]}) producía {tags: {0: "b"}}. La nueva versión solo recurre cuando ambos lados son objetos simples.

Render batch en paralelo. batchFactory renderizaba los PNG en bucle serializado: una exportación de 1000 cartas tardaba una eternidad. Ahora es un pool de workers con concurrencia configurable (4 por defecto), que conserva el orden de los resultados escribiendo en un array predimensionado:

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

En una exportación de 1000 personajes, eso transformó una pausa para el café en un "¿ya terminó?".

Un mensaje de error sharp que dice algo. buildPng importa sharp de forma perezosa porque es una dependencia opcional que no quieres imponer a los usuarios solo-SVG. El viejo catch tragaba el error real y siempre decía "sharp is required." Si el fallo real era un conflicto de versión o un problema de bindings nativos, pasabas diez minutos reinstalando un paquete ya instalado. La nueva versión te sigue diciendo que lo instales, pero incluye el error subyacente.

Lo que sigue

El motor genético es el sitio ideal para seguir iterando: aún no hay suite de tests, así que los invariantes de coherencia ("un personaje brasileño de ascendencia esteasiática nunca tendrá ojos negro azabache con pelo platino") solo los aseguran los pesos. Añadir bun test o vitest y escribir un test de coherencia que lance diez mil randomizeFromCountry por país es el próximo paso.

Os traços que têm um eixo real de dominância (pele, olhos, cabelo) são resolvidos por uma lista ordenada explícita, o escuro domina o claro, os olhos castanhos/pretos dominam o azul, o preto azeviche domina o loiro :

// Ordem de dominância do cabelo : do mais recessivo ao mais dominante
const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // o mais recessivo
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // o mais dominante
] as const;

resolveByRank acha o índice de cada pai, pega o mais alto em uma combinação de alelos "dominante" e o mais baixo em "recessiva". As cores fantasy (rosa pastel, lilás) não estão na ordem, elas fazem cara ou coroa 50/50, que é o comportamento certo : não são biológicas, então dominância não faz sentido.

As sardas modelam MC1R : 75% se os dois pais têm, 25% se só um tem, 0% se nenhum. A barba está ligada ao SRY : removida se o filho for mulher, senão herdada do pai que tinha. O corte de cabelo não tem nada de biológico, é uma escolha cultural, então o filho sorteia no próprio pool de gênero, preservando a textura se possível.

Nada disso é genética digna de publicação. É uma camada de sensação : as crianças parecem uma mistura plausível dos pais, não a média de dois desconhecidos.

As partes de engenharia menos glamourosas que contaram

Alguns detalhes pouco visíveis mas que mereceram seu lugar no diff :

Um pick mais seguro. O original devolvia undefined convertido em T em array vazio. Com strict + noUncheckedIndexedAccess em TypeScript, é uma mentira que o compilador assina. A nova versão lança um RangeError, pego na hora no local da chamada em vez de produzir props undefined três níveis abaixo.

Um deepMerge que não corrompe arrays. A recursão antiga ativava assim que o valor de origem era um objeto, mesmo que o destino fosse null ou um array. merge({tags: ["a"]}, {tags: ["b"]}) produzia {tags: {0: "b"}}. A nova versão só recorre quando os dois lados são objetos simples.

Render batch em paralelo. batchFactory renderizava os PNG em loop serializado, uma exportação de 1000 cartas levava uma eternidade. Agora é um pool de workers com concorrência configurável (4 por padrão), que preserva a ordem dos resultados escrevendo em um array pré-dimensionado :

// Worker do pool : pega o próximo índice, renderiza e salva no lugar certo
const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

Em uma exportação de 1000 personagens, isso transformou uma pausa para o café em um "já acabou ?"

Uma mensagem de erro sharp que diz alguma coisa. buildPng importa o sharp de forma preguiçosa porque é uma dependência opcional que você não quer impor a usuários só de SVG. O catch antigo engolia o erro real e dizia sempre "sharp is required." Se a falha real era um conflito de versão ou um problema de bindings nativos, você passava dez minutos reinstalando um pacote já instalado. A nova versão continua mandando instalar, mas inclui o erro subjacente.

O próximo passo

O módulo está em 1.1.1 no repositório character-factory. O motor genético é o lugar ideal para continuar iterando, ainda não há suíte de testes, então os invariantes de coerência ("um personagem brasileiro de ascendência leste-asiática nunca vai ter olhos pretos azeviche com cabelo platinado") só são garantidos pelos pesos. Adicionar bun test ou vitest e escrever um teste de coerência que roda dez mil randomizeFromCountry por país é o próximo passo.

O próprio Kurekuta está privado por enquanto, mas cada carta que você um dia vir nele é só um blob CharacterConfig e um buildPng() de existir.

Apa yang ia lakukan

Snippet terkecil yang berguna :

import { CharacterFactory, Country, Mood } from "character-factory";

  .setMood(Mood.Happy)

Rangkaian sederhana ini mengambil etnis yang dibobot menurut demografi Jepang, mengambil warna kulit dan warna rambut yang cocok, memilih potongan dari subgrup gender yang benar, lalu mengunci mata/alis/mulut ke mode "bahagia". Hasilnya keluar sebagai SVG atau, dengan sharp terpasang, sebagai PNG dalam ukuran berapa pun.

Satu karakter hanyalah objek CharacterConfig -- wajah, rambut, aksesori, presentasi. Builder mengubahnya secara internal, dan kamu bisa mengekspornya sebagai JSON, base64 atau berkas, lalu memuatnya ulang secara identik. Untuk Kurekuta ini krusial : kartu menyimpan config, bukan gambar yang dirender. Jadi seninya selalu bisa direproduksi dan ukuran kartu tetap mungil.

Opsi DiceBear adalah pemilih seragam. Beri ["#ffdbb4", "#2c1b18"] untuk warna kulit dan kamu dapat salah satunya dengan probabilitas sama -- OK untuk logo, tidak berguna untuk "kasih saya karakter dari Brasil."

Mesin genetika kecil

Fungsi yang paling saya nikmati : projectChild. Dua factory bisa menghasilkan anak yang sifatnya diwarisi dengan dominansi biologis kira-kira :

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

Di balik kapnya, ini model yang sengaja mungil. Setiap orang tua membawa genotipe 2 alel, satu diambil dari tiap sisi, digabung jadi dominan atau resesif :

  return a === "D" || b === "D" ? "dominant" : "recessive";
}

Sifat yang punya sumbu dominansi nyata (kulit, mata, rambut) diselesaikan lewat daftar terurut eksplisit -- gelap mendominasi terang, mata cokelat/hitam mendominasi biru, hitam pekat mendominasi pirang :

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // paling resesif
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // paling dominan

resolveByRank menemukan indeks tiap orang tua, mengambil yang tertinggi pada kombinasi alel "dominan" dan yang terendah pada "resesif". Warna fantasi (pink pastel, lila) tidak ada dalam urutan -- mereka lempar koin 50/50, yang memang perilaku benar : mereka tidak biologis, jadi dominansi tidak bermakna.

Bintik-bintik memodelkan MC1R : 75% kalau kedua orang tua punya, 25% kalau satu saja yang membawa, 0% kalau tidak ada. Jenggot terkait SRY : dihapus kalau anaknya perempuan, kalau tidak diwarisi dari orang tua yang punya. Potongan rambut tidak ada biologisnya -- itu pilihan budaya, jadi anak mengambil dari pool gendernya sendiri, dengan mempertahankan tekstur kalau memungkinkan.

Tidak ada satu pun dari ini genetika layak publikasi. Ini lapisan rasa : anak-anak mirip campuran yang masuk akal dari orang tua mereka, bukan rata-rata dari dua orang asing.

Bagian rekayasa yang kurang glamor tapi penting

Beberapa detail tak terlihat tapi layak masuk diff :

pick yang lebih aman. Yang asli mengembalikan undefined yang di cast jadi T pada array kosong. Dengan strict + noUncheckedIndexedAccess di TypeScript, itu kebohongan yang ditandatangani kompiler. Versi baru melempar RangeError -- tertangkap langsung di tempat panggilan alih-alih menghasilkan prop undefined tiga tingkat lebih bawah.

deepMerge yang tidak merusak array. Rekursi lama aktif begitu nilai sumber adalah objek, bahkan kalau targetnya null atau array. merge({tags: ["a"]}, {tags: ["b"]}) menghasilkan {tags: {0: "b"}}. Versi baru hanya berekursi kalau kedua sisi objek polos.

Render batch secara paralel. batchFactory merender PNG dalam loop terserialisasi -- ekspor 1000 kartu memakan waktu lama. Sekarang ini pool worker dengan konkurensi yang bisa dikonfigurasi (4 secara bawaan), yang menjaga urutan hasil dengan menulis ke array yang sudah berukuran pas :

Pada ekspor 1000 karakter, ini mengubah jeda ngopi menjadi "loh sudah selesai?"

Pesan error sharp yang mengatakan sesuatu. buildPng mengimpor sharp secara malas karena itu dependensi opsional yang tidak ingin kamu paksakan ke pengguna SVG-only. Catch lama menelan error asli dan selalu bilang "sharp is required." Kalau kegagalan sebenarnya adalah konflik versi atau masalah binding native, kamu menghabiskan sepuluh menit menginstal ulang paket yang sudah terpasang. Versi baru tetap menyuruhmu menginstalnya, tapi menyertakan error yang mendasarinya.

Selanjutnya

Modulnya ada di 1.1.1 di repositori character-factory. Mesin genetikanya tempat ideal untuk terus beriterasi -- belum ada rangkaian tes, jadi invarian konsistensi ("karakter Brasil keturunan Asia-timur tidak akan pernah bermata hitam pekat dengan rambut platinum") hanya dijamin oleh bobot. Menambahkan bun test atau vitest dan menulis tes konsistensi yang menjalankan sepuluh ribu randomizeFromCountry per negara, itu langkah berikutnya.

Kurekuta sendiri masih privat untuk sekarang, tapi setiap kartu yang suatu hari akan kamu lihat di dalamnya hanyalah blob CharacterConfig dan buildPng() untuk menjadi ada.

मुझे Kurekuta के लिए हजारों विश्वसनीय और अलग अवतार चाहिए थे, एक निजी कार्ड गेम प्रोजेक्ट जहाँ हर कार्ड में पात्र का "DNA" होता है जिसे रेंडर इंजन पोर्ट्रेट में बदलता है। बना बनाया पैक खरीदना दिख जाता। प्रति पात्र seed वाले DiceBear अवतार बनाना बकवास देता था : जापानी ब्रह्मांड का कार्ड स्कैंडिनेवियाई गोरी पर पड़ सकता था, और दो "भाई बहन" अजनबियों जैसे लगते थे।

इसलिए मैंने character-factory लिखा, DiceBear के Lorelei संग्रह के ऊपर एक TypeScript मॉड्यूल जो तीन सुविधाएँ लाता है जो अकेले DiceBear नहीं देता : सुसंगत जनसांख्यिकीय प्रोफाइल, छोटा आनुवंशिकी इंजन, और गेम लूप से इस्तेमाल में सुखद प्रवाही builder।

यह क्या करता है

सबसे छोटा उपयोगी snippet :

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // भारित नस्ल → सुसंगत त्वचा/बाल/कट/दाढ़ी
  .setMood(Mood.Happy)
  .buildSvg();

यह साधारण शृंखला जापानी जनसांख्यिकी से भारित नस्ल चुनती है, एक साथ जाने वाला रंग और बालों का रंग निकालती है, सही लिंग उपसमूह से कट चुनती है, फिर आँखें/भौंहें/मुँह "खुश" मोड में लॉक करती है। परिणाम SVG में निकलता है या, sharp स्थापित होने पर, किसी भी आकार में PNG में।

एक पात्र सिर्फ एक CharacterConfig ऑब्जेक्ट है, चेहरा, बाल, सहायक वस्तुएँ, प्रस्तुति। builder इसे अंदर संशोधित करता है, और तुम इसे JSON, base64 या फाइल में निर्यात कर सकते हो, फिर हूबहू फिर से लोड कर सकते हो। Kurekuta के लिए यह महत्वपूर्ण है : एक कार्ड रेंडर की गई छवि नहीं, कॉन्फ़िग संग्रहित करता है। इसलिए कला हमेशा पुनरुत्पादनीय है और कार्ड का आकार छोटा रहता है।

सुसंगत जनसांख्यिकीय प्रोफाइल, बेतरतीब पिक्सेल नहीं

DiceBear विकल्प एकसमान चयनकर्ता हैं। त्वचा रंग के लिए ["#ffdbb4", "#2c1b18"] दो और तुम्हें समान संभावना के साथ एक या दूसरा मिलेगा, लोगो के लिए ठीक, "मुझे ब्राजील का पात्र दो" के लिए बेकार।

छोटा आनुवंशिकी इंजन

वह फंक्शन जिस पर मैं सबसे ज्यादा मजे से काम किया : projectChild। दो factory एक बच्चा बना सकती हैं जिसके लक्षण अनुमानित जैविक प्रभुत्व के साथ विरासत में मिलते हैं :

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);

हुड के नीचे, यह जानबूझकर छोटा मॉडल है। हर माता पिता 2 एलील वाला जीनोटाइप रखते हैं, हर तरफ से एक निकाला गया, प्रमुख या अप्रभावी में संयोजित :

resolveByRank हर माता पिता का सूचकांक खोजता है, "प्रमुख" एलील संयोजन पर उच्चतम लेता है और "अप्रभावी" पर निम्नतम। फैंटेसी रंग (पेस्टल गुलाबी, लाइलैक) क्रम में नहीं हैं, वे 50/50 सिक्का उछाल करते हैं, जो सही व्यवहार है : वे जैविक नहीं हैं, इसलिए प्रभुत्व का कोई अर्थ नहीं।

झाइयाँ MC1R मॉडल करती हैं : 75% अगर दोनों माता पिता में हैं, 25% अगर सिर्फ एक में है, 0% अगर किसी में नहीं। दाढ़ी SRY से जुड़ी है : अगर बच्चा लड़की है तो हटाई जाती है, वरना उस माता पिता से विरासत में मिलती है जिसके पास थी। बाल कट में कुछ जैविक नहीं है, यह सांस्कृतिक चुनाव है, इसलिए बच्चा अपने लिंग पूल से चुनता है, संभव होने पर बनावट संरक्षित करते हुए।

इसमें से कुछ भी प्रकाशन योग्य आनुवंशिकी नहीं है। यह एहसास की परत है : बच्चे अपने माता पिता के प्रशंसनीय मिश्रण जैसे लगते हैं, दो अजनबियों के औसत जैसे नहीं।

कम आकर्षक इंजीनियरिंग हिस्से जो मायने रखते थे

कुछ कम दिखने वाले विवरण लेकिन जिन्होंने diff में अपनी जगह कमाई :

ज्यादा सुरक्षित pick। मूल खाली सरणी पर T में cast undefined लौटाता था। TypeScript में strict + noUncheckedIndexedAccess के साथ, यह एक झूठ है जिस पर कंपाइलर हस्ताक्षर करता है। नया संस्करण RangeError फेंकता है, तीन स्तर नीचे undefined props बनाने के बजाय कॉल साइट पर तुरंत पकड़ा गया।

deepMerge जो सरणियों को भ्रष्ट नहीं करता। पुराना recursion तब सक्रिय होता था जब स्रोत मान ऑब्जेक्ट था, भले ही लक्ष्य null या सरणी हो। merge({tags: ["a"]}, {tags: ["b"]}) {tags: {0: "b"}} बनाता था। नया संस्करण सिर्फ तभी recurse करता है जब दोनों तरफ सादे ऑब्जेक्ट हों।

समानांतर में बैच रेंडर। batchFactory PNG को क्रमिक लूप में रेंडर करता था, 1000 कार्ड निर्यात में घंटों लगते थे। अब यह कॉन्फ़िगर करने योग्य समवर्तीता (डिफ़ॉल्ट 4) वाला worker पूल है, जो पूर्व आकार वाली सरणी में लिखकर परिणामों का क्रम संरक्षित करता है :

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

1000 पात्रों के निर्यात पर, इसने चाय ब्रेक को "क्या पहले ही खत्म हो गया ?" में बदल दिया।

sharp त्रुटि संदेश जो कुछ कहता है। buildPng sharp को आलसी आयात करता है क्योंकि यह वैकल्पिक निर्भरता है जिसे तुम सिर्फ SVG वाले उपयोगकर्ताओं पर नहीं थोपना चाहते। पुराना catch असली त्रुटि निगल जाता था और हमेशा कहता था "sharp is required."। अगर असली विफलता संस्करण संघर्ष या नेटिव बाइंडिंग समस्या थी, तो तुम पहले से स्थापित पैकेज फिर से स्थापित करने में दस मिनट बिताते थे। नया संस्करण तुम्हें हमेशा इसे स्थापित करने को कहता है, लेकिन अंतर्निहित त्रुटि शामिल करता है।

आगे

मॉड्यूल character-factory रिपॉजिटरी पर 1.1.1 में है। आनुवंशिकी इंजन दोहराते रहने के लिए आदर्श जगह है, अभी कोई परीक्षण सुइट नहीं है, इसलिए सुसंगतता अपरिवर्तनीय ("पूर्व एशियाई वंश का ब्राजीलियाई पात्र प्लेटिनम बालों के साथ गहरे काले आँखें कभी नहीं पाएगा") सिर्फ भारों से सुनिश्चित हैं। bun test या vitest जोड़ना और सुसंगतता परीक्षण लिखना जो प्रति देश दस हजार randomizeFromCountry चलाता है, अगला चरण है।

Kurekuta खुद अभी निजी है, लेकिन हर कार्ड जो तुम एक दिन उसमें देखोगे सिर्फ एक CharacterConfig blob और अस्तित्व का एक buildPng() है।

بناء character-factory : أفاتار بنظام جيني

احتجت آلاف الأفاتار الموثوقة والمميزة لـKurekuta، وهو مشروع لعبة ورق خاص حيث تحمل كل بطاقة "DNA" شخصية يحوّله محرك العرض إلى بورتريه. شراء حزمة جاهزة كان سيُرى. توليد أفاتار DiceBear بالـseed لكل شخصية أعطى أي شيء : بطاقة بعالم ياباني قد تقع على شقراء اسكندنافية، و"أخ وأخت" كانا يشبهان غريبين.

فكتبت character-factory، وهي وحدة TypeScript فوق مجموعة Lorelei من DiceBear تضيف ثلاث مزايا لا يعطيها DiceBear وحده : ملفات ديموغرافية متسقة، ومحرك جينات صغير، وباني انسيابي ممتع الاستخدام من حلقة لعبة.

ما الذي يفعله

أصغر مقتطف مفيد :

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // عرق موزون ← بشرة/شعر/قصة/لحية متسقة
  .setMood(Mood.Happy)
  .buildSvg();

هذه السلسلة البسيطة تسحب عرقا موزونا بالديموغرافيا اليابانية، وتسحب لون بشرة ولون شعر يتوافقان، وتختار قصة من المجموعة الفرعية الصحيحة للجنس، ثم تقفل العيون/الحاجبين/الفم على وضع "سعيد". النتيجة تخرج SVG أو، مع تثبيت sharp، PNG بأي حجم.

الشخصية ليست إلا كائن CharacterConfig، وجه وشعر وإكسسوارات وعرض. الباني يعدّله داخليا، ويمكنك تصديره JSON أو base64 أو ملفا، ثم إعادة تحميله كما هو. بالنسبة لـKurekuta هذا حاسم : البطاقة تخزن الإعداد، لا الصورة المعروضة. وهكذا يبقى الفن دائما قابلا لإعادة الإنتاج ويبقى حجم البطاقة ضئيلا.

ملفات ديموغرافية متسقة، لا بكسل عشوائي

خيارات DiceBear منتقاة منتظمة. مرر ["#ffdbb4", "#2c1b18"] للون البشرة وستحصل على أحدهما أو الآخر بنفس الاحتمال، جيد لشعار، وعديم الفائدة لـ"أعطني شخصية من البرازيل."

يضمّن character-factory خط أنابيب بلد ← عرق ← سمات :

  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...

كل طبقة سحب موزون. الأوزان ليست أطروحة اجتماعية، بل استدلال يمنع "القادم من اليابان" من إنتاج أحمر و"القادم من السويد" من إنتاج أسود فاحم. كل خط الأنابيب يتلخص في استدعاء واحد : setCountry(country) أو randomizeFromCountry(country, gender?).

محرك جينات صغير

الدالة التي استمتعت بها أكثر : projectChild. يمكن لمصنعين إنتاج طفل تُورَّث سماته بدومينانس بيولوجية تقريبية :

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

تحت الغطاء، نموذج صغير عمدا. كل والد يحمل نمطا جينيا بأليلين، واحد مسحوب من كل جهة، مدمج في سائد أو متنحٍ :

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

السمات ذات محور دومينانس حقيقي (بشرة، عيون، شعر) تُحل بقائمة مرتبة صريحة، الداكن يسود الفاتح، والعيون البنية/السوداء تسود الزرقاء، والأسود الفاحم يسود الأشقر :

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // الأكثر تنحيا
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,

تجد resolveByRank فهرس كل والد، وتأخذ الأعلى على تركيبة أليلات "سائدة" والأدنى على "متنحية". ألوان الفانتازيا (وردي باستيل، ليلكي) ليست في الترتيب، بل تقوم بقرعة 50/50، وهو السلوك الصحيح : فهي ليست بيولوجية، لذا لا معنى للدومينانس.

النمش يصمم MC1R : 75% إذا كان لدى الوالدين، و25% إذا حملها واحد فقط، و0% إذا لم يحملها أحد. اللحية مرتبطة بـSRY : تُزال إذا كان الطفل أنثى، وإلا تُورَّث من الوالد الذي كانت لديه. قصة الشعر لا بيولوجيا فيها، بل خيار ثقافي، لذا يسحب الطفل من مجموعته الجندرية الخاصة، مع الحفاظ على الملمس إن أمكن.

لا شيء من هذا جينات تصلح للنشر. إنها طبقة إحساس : الأطفال يشبهون مزيجا معقولا لوالديهم، لا متوسط غريبين.

الأجزاء الهندسية الأقل بريقا التي كانت مهمة

بعض التفاصيل قليلة الظهور لكنها استحقت مكانها في الـdiff :

pick أكثر أمانا. الأصلي كان يعيد undefined مصبوبا كـT على مصفوفة فارغة. مع strict + noUncheckedIndexedAccess في TypeScript، هذه كذبة يوقعها المترجم. النسخة الجديدة ترمي RangeError، تُمسك فورا في موقع الاستدعاء بدلا من إنتاج props بقيمة undefined ثلاثة مستويات أدناه.

deepMerge لا يفسد المصفوفات. التكرار القديم كان ينشط بمجرد أن تكون القيمة المصدر كائنا، حتى لو كان الهدف null أو مصفوفة. merge({tags: ["a"]}, {tags: ["b"]}) كان ينتج {tags: {0: "b"}}. النسخة الجديدة لا تعيد التكرار إلا عندما يكون الطرفان كائنين بسيطين.

عرض دفعي بالتوازي. كان batchFactory يعرض الـPNG في حلقة متسلسلة، فتصدير 1000 بطاقة كان يستغرق دهورا. صار الآن مجموعة workers بتزامن قابل للضبط (4 افتراضيا)، تحفظ ترتيب النتائج بالكتابة في مصفوفة مسبقة الأبعاد :

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

في تصدير 1000 شخصية، حول هذا استراحة قهوة إلى "هل انتهى فعلا ؟"

رسالة خطأ sharp تقول شيئا. يستورد buildPng مكتبة sharp بكسل لأنها تبعية اختيارية لا تريد فرضها على مستخدمي SVG-only. الـcatch القديم كان يبتلع الخطأ الحقيقي ويقول دائما "sharp is required." فإذا كان الفشل الحقيقي تعارض إصدار أو مشكلة bindings أصلية، قضيت عشر دقائق تعيد تثبيت حزمة مثبتة فعلا. النسخة الجديدة تطلب التثبيت دائما، لكنها تضمّن الخطأ الكامن.

التالي

الوحدة في 1.1.1 على مستودع character-factory. المحرك الجيني هو المكان المثالي لمواصلة التكرار، فلا توجد بعد سلسلة اختبارات، لذا ثوابت الاتساق ("شخصية برازيلية من أصل شرق آسيوي لن تملك أبدا عيونا سوداء فاحمة مع شعر بلاتيني") لا يضمنها إلا الأوزان. إضافة bun test أو vitest وكتابة اختبار اتساق يشغّل عشرة آلاف randomizeFromCountry لكل بلد، هي الخطوة التالية.

Kurekuta نفسه خاص حاليا، لكن كل بطاقة ستراها فيه يوما ما ليست إلا blob من CharacterConfig واستدعاء buildPng() من الوجود.

Xây character-factory : avatar với hệ di truyền

Tôi cần hàng nghìn avatar đáng tin và khác biệt cho Kurekuta -- một dự án game thẻ bài riêng, nơi mỗi lá bài chứa một "ADN" nhân vật mà động cơ render biến thành chân dung. Mua một gói làm sẵn, nhìn là biết ngay. Tạo avatar DiceBear theo seed từng nhân vật, cho ra thứ linh tinh : một lá bài bối cảnh Nhật Bản có thể rơi vào cô tóc vàng Scandinavia, và hai "anh chị em" trông như người xa lạ.

Vì vậy tôi viết character-factory -- một module TypeScript trên bộ sưu tập Lorelei của DiceBear mang lại ba tính năng DiceBear đơn lẻ không có : hồ sơ nhân khẩu nhất quán, một động cơ di truyền nhỏ, và một builder mượt dễ dùng từ vòng lặp game.

Nó làm gì

Snippet nhỏ nhất hữu ích :

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // dân tộc có trọng số → da/tóc/kiểu/râu nhất quán
  .setMood(Mood.Happy)
  .buildSvg();

Chuỗi đơn giản này bốc một dân tộc có trọng số theo nhân khẩu Nhật Bản, rút màu da và màu tóc hợp nhau, chọn kiểu tóc trong đúng nhóm giới tính, rồi khóa mắt/lông mày/miệng ở chế độ "vui". Kết quả ra SVG hoặc, khi đã cài sharp, ra PNG ở bất kỳ kích thước nào.

Một nhân vật chỉ là một object CharacterConfig -- khuôn mặt, tóc, phụ kiện, trình bày. Builder sửa nó bên trong, và bạn có thể xuất ra JSON, base64 hoặc tệp, rồi tải lại giống hệt. Với Kurekuta điều này then chốt : một lá bài lưu config, không lưu ảnh đã render. Nhờ vậy art luôn tái tạo được và kích thước mỗi lá bài vẫn tí hon.

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {

    { color: SkinColor.Light,  weight: 35 },

Mỗi lớp là một lần rút có trọng số. Các trọng số không phải luận án xã hội học -- đó là heuristic ngăn "đến từ Nhật Bản" sinh ra tóc đỏ và "đến từ Thụy Điển" sinh ra tóc đen tuyền. Toàn bộ pipeline gói trong một gọi duy nhất : setCountry(country) hoặc randomizeFromCountry(country, gender?).

Một động cơ di truyền nhỏ

Hàm tôi chơi vui nhất : projectChild. Hai factory có thể sinh một đứa con mà đặc điểm được thừa hưởng với tính trội sinh học gần đúng :

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

Bên dưới, đó là một mô hình cố ý tí hon. Mỗi bố mẹ mang một kiểu gen 2 alen, một rút từ mỗi bên, kết hợp thành trội hoặc lặn :

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

Các đặc điểm có trục trội thật (da, mắt, tóc) được giải bằng danh sách thứ tự rõ ràng -- tối trội hơn sáng, mắt nâu/đen trội hơn xanh, đen tuyền trội hơn vàng hoe :

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // lặn nhất
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // trội nhất
] as const;

resolveByRank tìm index của mỗi bố mẹ, lấy index cao hơn trên tổ hợp alen "trội" và thấp hơn trên "lặn". Màu fantasy (hồng pastel, tử đinh hương) không nằm trong thứ tự -- chúng tung đồng xu 50/50, đó là hành vi đúng : chúng không sinh học, nên tính trội vô nghĩa.

Tàn nhang mô hình hóa MC1R : 75% nếu cả hai bố mẹ đều có, 25% nếu chỉ một bên mang, 0% nếu không ai có. Râu gắn với SRY : bỏ nếu con là nữ, ngược lại thừa hưởng từ bên bố mẹ có râu. Kiểu tóc không có gì sinh học -- đó là lựa chọn văn hóa, nên đứa con bốc từ pool giới tính của chính nó, giữ lại chất tóc nếu có thể.

Không gì trong số này là di truyền đáng đăng báo. Đó là một lớp cảm nhận : lũ trẻ trông như hỗn hợp hợp lý của bố mẹ chúng, không phải trung bình của hai người xa lạ.

Những phần kỹ thuật kém hào nhoáng nhưng đáng giá

Vài chi tiết ít thấy nhưng xứng đáng có chỗ trong diff :

Một pick an toàn hơn. Bản gốc trả về undefined ép thành T trên mảng rỗng. Với strict + noUncheckedIndexedAccess trong TypeScript, đó là lời nói dối mà trình biên dịch ký tên. Phiên bản mới ném RangeError -- bắt ngay tại chỗ gọi thay vì sinh prop undefined ba tầng sâu hơn.

Một deepMerge không làm hỏng mảng. Đệ quy cũ kích hoạt hễ giá trị nguồn là object, dù đích là null hay mảng. merge({tags: ["a"]}, {tags: ["b"]}) sinh ra {tags: {0: "b"}}. Phiên bản mới chỉ đệ quy khi cả hai bên đều là object thuần.

Render batch song song. batchFactory render PNG trong vòng lặp nối tiếp -- xuất 1000 lá bài mất cả buổi. Giờ đây là pool worker với đồng thời cấu hình được (mặc định 4), giữ thứ tự kết quả bằng cách ghi vào mảng định kích thước trước :

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

Trên một lần xuất 1000 nhân vật, việc đó biến giờ nghỉ cà phê thành "xong rồi á?"

Một thông báo lỗi sharp nói được điều gì. buildPng import sharp lười vì đó là phụ thuộc tùy chọn mà bạn không muốn áp lên người dùng chỉ cần SVG. Catch cũ nuốt lỗi thật và luôn nói "sharp is required." Nếu lỗi thực là xung đột phiên bản hay vấn đề binding native, bạn mất mười phút cài lại một gói đã cài rồi. Phiên bản mới vẫn bảo bạn cài nó, nhưng kèm lỗi gốc bên trong.

Bản thân Kurekuta hiện vẫn riêng tư, nhưng mỗi lá bài bạn một ngày nào đó thấy trong đó chỉ là một blob CharacterConfig và một buildPng() chờ tồn tại.

สร้าง character-factory : อวาตาร์ที่มีระบบพันธุกรรม

ผมต้องการอวาตาร์ที่ดูสมจริงและแตกต่างกันเป็นพัน ๆ ตัวสำหรับ Kurekuta -- โปรเจกต์เกมการ์ดส่วนตัวที่การ์ดแต่ละใบมี "DNA" ของตัวละครที่เอนจินเรนเดอร์เปลี่ยนเป็นภาพพอร์ตเรต การซื้อแพ็คสำเร็จรูปก็ดูออก การสร้างอวาตาร์ DiceBear ด้วย seed ต่อตัวละครก็ให้ผลลัพธ์ที่ไม่แน่นอน : การ์ดแนวญี่ปุ่นอาจได้ตัวละครสาวผมบลอนด์สแกนดิเนเวีย และ "พี่น้อง" สองคนกลับดูไม่ใช่คนรู้จักกันเลย

ผมเลยเขียน character-factory -- โมดูล TypeScript ที่ทำงานบนชุด Lorelei ของ DiceBear ซึ่งเพิ่มสามสิ่งที่ DiceBear อย่างเดียวทำไม่ได้ : โปรไฟล์ประชากรที่สอดคล้องกัน, เอนจินพันธุกรรมขนาดเล็ก, และ builder ที่ใช้งานง่าย สะดวกต่อการเรียกใช้จากลูปเกม

มันทำอะไรได้บ้าง

ตัวอย่างสั้นที่สุดที่ใช้งานได้ :

import { CharacterFactory, Country, Mood } from "character-factory";

const svg = new CharacterFactory()
  .setCountry(Country.Japan)   // ถ่วงน้ำหนักเชื้อชาติ → ผิว/ผม/ทรงผม/หนวดเครา ที่สอดคล้องกัน
  .setMood(Mood.Happy)
  .buildSvg();

การเรียกใช้เพียงเท่านี้จะสุ่มเชื้อชาติโดยถ่วงน้ำหนักตามประชากรญี่ปุ่น, จับคู่สีผิวและสีผมที่เข้ากัน, เลือกทรงผมในกลุ่มย่อยตามเพศที่เหมาะสม, จากนั้นล็อคดวงตา/คิ้ว/ปากเป็นโหมด "มีความสุข" ผลลัพธ์ที่ได้คือ SVG หรือหากติดตั้ง sharp ก็จะได้ PNG ที่ขนาดตามต้องการ

ตัวละครแต่ละตัวเป็นแค่อ็อบเจกต์ CharacterConfig -- ใบหน้า, ผม, อุปกรณ์เสริม, การนำเสนอ builder จะปรับเปลี่ยนภายใน และคุณสามารถส่งออกเป็น JSON, base64 หรือไฟล์ แล้วโหลดกลับมาเหมือนเดิม สำหรับ Kurekuta นี่เป็นสิ่งสำคัญ : การ์ดเก็บ config ไม่ใช่ภาพที่เรนเดอร์แล้ว ดังนั้นอาร์ตเวิร์กจึงสามารถสร้างซ้ำได้เสมอ และขนาดการ์ดก็เล็กมาก

โปรไฟล์ประชากรที่สอดคล้องกัน ไม่ใช่พิกเซลสุ่ม

ตัวเลือกของ DiceBear เป็นตัวเลือกแบบสม่ำเสมอ ใส่ ["#ffdbb4", "#2c1b18"] สำหรับสีผิว แล้วคุณจะได้สีใดสีหนึ่งด้วยความน่าจะเป็นเท่ากัน -- ใช้ได้กับโลโก้ แต่ไร้ประโยชน์สำหรับ "ขอตัวละครจากบราซิลหน่อย"

character-factory มาพร้อมกับไปป์ไลน์ ประเทศ → เชื้อชาติ → ลักษณะ :

// สิ่งที่อยู่ในโมดูล :
ethnicitiesByCountry[Country.Brazil] = [
  { ethnicity: Ethnicity.WestEuropean,  weight: 35 },
  { ethnicity: Ethnicity.BlackAfrican,  weight: 25 },
  { ethnicity: Ethnicity.Latino,        weight: 30 },
  // ...
];

ETHNICITY_PROFILES[Ethnicity.EastAsian] = {
  skinColors: [
    { color: SkinColor.Light,  weight: 35 },
    { color: SkinColor.Warm,   weight: 40 },
    { color: SkinColor.Medium, weight: 20 },
    // ...
  ],
  hairColors: [/* ส่วนใหญ่เป็นสีดำ/น้ำตาลเข้ม ไม่มีบลอนด์ */],
  hairCuts:   { male: [...], female: [...] },
  beardProbability: 0.15,
};

แต่ละชั้นเป็นการสุ่มแบบถ่วงน้ำหนัก ค่าน้ำหนักไม่ใช่วิทยานิพนธ์ทางสังคม -- เป็นฮิวริสติกที่ป้องกันไม่ให้ "มาจากญี่ปุ่น" ได้คนผมแดง หรือ "มาจากสวีเดน" ได้คนผมดำสนิท ทั้งไปป์ไลน์ทำงานด้วยการเรียกเพียงครั้งเดียว : setCountry(country) หรือ randomizeFromCountry(country, gender?)

เอนจินพันธุกรรมขนาดเล็ก

ฟังก์ชันที่สนุกที่สุดในการเขียน : projectChild สอง factories สามารถสร้างลูกที่มีลักษณะสืบทอดแบบเด่นทางชีวภาพโดยประมาณ :

const parentA = new CharacterFactory().setCountry(Country.Sweden);
const parentB = new CharacterFactory().setCountry(Country.Japan);
const kid     = parentA.projectChild(parentB.getConfig());

เบื้องหลังเป็นโมเดลที่ตั้งใจให้เล็กมาก พ่อแม่แต่ละคนมีจีโนไทป์แบบ 2 อัลลีล สุ่มจากแต่ละฝ่าย รวมกันเป็นเด่นหรือด้อย :

function combine(a: Allele, b: Allele): "dominant" | "recessive" {
  return a === "D" || b === "D" ? "dominant" : "recessive";
}

ลักษณะที่มีแกนความเด่นจริง (ผิว, ดวงตา, ผม) ถูกกำหนดโดยลิสต์ลำดับที่ชัดเจน -- สีเข้มเด่นกว่าสีอ่อน, ตาสีน้ำตาล/ดำเด่นกว่าสีฟ้า, ผมดำสนิทเด่นกว่าผมบลอนด์ :

const HAIR_DOMINANCE_ORDER = [
  HairColor.LightBlonde,   // ด้อยที่สุด
  HairColor.GoldenBlonde,
  HairColor.HoneyBlonde,
  HairColor.Auburn,
  HairColor.Red,
  HairColor.Copper,
  HairColor.LightBrown,
  HairColor.Brown,
  HairColor.DarkBrown,
  HairColor.SoftBlack,
  HairColor.JetBlack,      // เด่นที่สุด
] as const;

resolveByRank หา index ของพ่อแม่แต่ละคน เลือกค่าสูงสุดเมื่อรวมอัลลีลแบบ "เด่น" และค่าต่ำสุดเมื่อเป็น "ด้อย" สีแฟนตาซี (ชมพูพาสเทล, ม่วง) ไม่ได้อยู่ในลำดับ -- มันสุ่ม 50/50 ซึ่งเป็นพฤติกรรมที่ถูกต้อง : มันไม่ใช่ลักษณะทางชีวภาพ ดังนั้นความเด่นจึงไม่มีความหมาย

กระจุดจำลอง MC1R : 75% ถ้าพ่อแม่ทั้งสองมี, 25% ถ้ามีเพียงคนเดียว, 0% ถ้าไม่มี เคราขึ้นอยู่กับ SRY : ถูกลบออกถ้าเด็กเป็นผู้หญิง ไม่เช่นนั้นก็สืบทอดจากพ่อแม่ที่มีเครา ทรงผมไม่ใช่เรื่องชีวภาพ -- เป็นเรื่องวัฒนธรรม ดังนั้นเด็กจึงสุ่มจาก pool ของเพศตนเอง โดยคง texture ไว้ถ้าเป็นไปได้

ไม่มีอะไรที่เป็นพันธุศาสตร์ระดับตีพิมพ์ มันเป็นชั้นของความรู้สึก : เด็กดูเหมือนการผสมผสานที่ plausible ของพ่อแม่ ไม่ใช่ค่าเฉลี่ยของคนสองคนที่ไม่รู้จัก

ส่วนวิศวกรรมที่ไม่สวยหรูแต่สำคัญ

มีบางอย่างที่ไม่เด่นแต่คุ้มค่าที่อยู่ใน diff :

pick ที่ปลอดภัยขึ้น. ต้นฉบับคืนค่า undefined ที่ cast เป็น T เมื่อเจออาเรย์ว่าง ด้วย strict + noUncheckedIndexedAccess ใน TypeScript นั่นคือการโกหกที่คอมไพเลอร์ยอมรับ เวอร์ชันใหม่โยน RangeError -- ถูกจับทันทีที่จุดเรียกแทนที่จะสร้าง props undefined สามระดับลึกลงไป

deepMerge ที่ไม่ทำให้อาเรย์เสียหาย. การเรียกซ้ำแบบเก่าทำงานเมื่อค่าต้นทางเป็นอ็อบเจกต์ แม้ว่าเป้าหมายจะเป็น null หรืออาเรย์ merge({tags: ["a"]}, {tags: ["b"]}) ให้ผลลัพธ์เป็น {tags: {0: "b"}} เวอร์ชันใหม่จะเรียกซ้ำเฉพาะเมื่อทั้งสองฝั่งเป็นอ็อบเจกต์ธรรมดา

เรนเดอร์แบบ batch แบบขนาน. batchFactory เคยเรนเดอร์ PNG เป็นลูปต่อเนื่อง -- การส่งออก 1,000 ใบใช้เวลานานมาก ตอนนี้เป็น pool ของ workers ที่ปรับระดับความขนานได้ (ค่าเริ่มต้น 4) ซึ่งรักษาลำดับผลลัพธ์โดยเขียนลงในอาเรย์ที่จองพื้นที่ไว้แล้ว :

const worker = async () => {
  while (true) {
    const i = nextIndex++;
    if (i >= count) return;
    // render and save
    results[i] = { index: i + 1, filePath, config: clone.getConfig() };
    done++;
    onProgress?.(done, count);
  }
};
await Promise.all(Array.from({ length: concurrency }, () => worker()));

ในการส่งออกตัวละคร 1,000 ตัว มันเปลี่ยนจาก "ไปชงกาแฟรอ" เป็น "เสร็จแล้วเหรอ?"

ข้อความข้อผิดพลาด sharp ที่มีความหมาย. buildPng import sharp แบบขี้เกียจเพราะมันเป็น dependency ตัวเลือกที่คุณไม่อยากบังคับผู้ใช้ที่ใช้แค่ SVG โค้ดจับข้อผิดพลาดแบบเก่ากลบข้อผิดพลาดจริงและบอกแค่ว่า "sharp is required." ถ้าความล้มเหลวจริงเป็นเรื่องเวอร์ชันขัดแย้งหรือปัญหา native bindings คุณจะเสียเวลาสิบนาทีลงใหม่ทั้งที่ติดตั้งไว้แล้ว เวอร์ชันใหม่ยังคงบอกให้ติดตั้ง แต่รวมข้อผิดพลาดที่แท้จริงไว้ด้วย

ต่อไป

โมดูลอยู่ที่เวอร์ชัน 1.1.1 บน repository character-factory เอนจินพันธุกรรมเป็นจุดที่เหมาะสำหรับการพัฒนาต่อ -- ยังไม่มีชุดทดสอบ ดังนั้น invariants ความสอดคล้อง ("ตัวละครบราซิลเชื้อสายเอเชียตะวันออกจะไม่มีวันมีตาสีดำสนิทกับผมสีพลาตินัม") จึงรับประกันด้วยน้ำหนักเท่านั้น การเพิ่ม bun test หรือ vitest และเขียนเทสต์ความสอดคล้องที่สุ่ม randomizeFromCountry หมื่นครั้งต่อประเทศ คือขั้นตอนถัดไป

Kurekuta เองยังเป็นโปรเจกต์ส่วนตัวในตอนนี้ แต่ทุกการ์ดที่คุณจะได้เห็นในอนาคตนั้นเป็นเพียง blob CharacterConfig และ buildPng() เท่านั้น
